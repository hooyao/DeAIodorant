4.5 图片上传到微博 CDN（关键突破！）
这是一个
关键的发现
：
execCommand('insertHTML')
插入 base64 data URL 虽然在编辑器中可见，但
保存草稿 API 会剥离 data URL
，图片不会持久化到草稿中。
解决方案
：利用 TipTap 编辑器的剪辑板事件处理器，通过
ClipboardEvent
粘贴图片文件，编辑器自动上传到微博 CDN 并替换为 CDN URL：
const bc = atob(b64);
const ba = new Uint8Array(bc.length);
for (let i = 0; i < bc.length; i++) ba[i] = bc.charCodeAt(i);
const blob = new Blob([ba], { type: 'image/png' });
const file = new File([blob], fileName, { type: 'image/png' });
const dt = new DataTransfer();
dt.items.add(file);
pm.dispatchEvent(new ClipboardEvent('paste', {
clipboardData: dt, bubbles: true, cancelable: true, composed: true
}));
上传成功后，编辑器自动将
的
src
替换为微博 CDN 链接，格式如：
https://wx3.sinaimg.cn/large/006zzmO3gy1iexwgl1h4sj30rs0fkgmt.jpg
已验证
：8 张图片（15KB~414KB）全部上传成功，总计约 1.4MB。

六、原因分析
6.1 为什么「下一步」按钮无法脚本触发？
微博头条编辑器使用
React + TipTap
SPA。「下一步」按钮绑定了复杂的内部验证逻辑：
1.
内容格式校验
：编辑器内容必须经过 TipTap 的 schema 验证（非纯 HTML 字符串）
2.
封面图检查
：可能需要设置封面图片
3.
React 合成事件
：
onClick
绑定在 React 的合成事件层，直接 DOM
click()
不触发 React 的 dispatch
4.
状态验证
：内部状态机检查编辑器
isDirty
、
hasContent
、
hasTitle
等标志
对比
华为云博客编辑器
，其
window.saveBlog()
函数可以直接调用绕过 UI 层。而微博头条编辑器
未暴露类似的全局函数
。
6.2 为什么 publish API 返回 500002？
可能的根因：
1.
草稿状态校验
：publish API 要求草稿在发布前处于特定状态（如已设置封面、已通过格式校验）
2.
内容长度限制
：14200 字符的 HTML 内容可能超出了某些隐式限制
3.
图片引用校验
：虽然 CDN URL 已保存，但发布流程可能检查图片是否经过编辑器完整处理（如裁剪、水印设置）

九、工程实践总结
技术选型建议
1.
能调 API 就别点按钮
：前端 UI 自动化的可靠性上限取决于前端框架。React SPA 的合成事件层比传统 jQuery/MVC 更难脚本化。
2.
优先寻找全局函数
：开发自动化脚本前，先在浏览器控制台搜索
window.saveBlog
、
window.publish
、
window.submit
等全局函数。这比模拟点击可靠 10 倍。
3.
持久化登录态
：
launchPersistentContext
是 Playwright 最实用的功能之一。一次登录，多次复用。
4.
剪辑板粘贴是 TipTap 图片上传的入口
：base64 data URL 在 TipTap 中不触发上传，必须通过真正的 ClipboardEvent 粘贴图片文件。

十、最终结论
自动化的可靠上限取决于前端框架的开放程度。
对于微博头条号，我们可以做到：
✅ 自动登录持久的化
✅ 自动填入标题 + 正文（TipTap execCommand）
✅ 自动上传图片到 CDN（ClipboardEvent paste）
✅ 自动保存草稿
但
无法跳过
「下一步」→「发布」这两步——React SPA 的验证层将按钮交互与内部状态机深度绑定，目前所有脚本方案均被拦截。
华为云社区的博客系统则友好得多
——
window.saveBlog()
+ blogging API 提供了完整的程序化发布能力。
对于内容创作者：如果追求全自动化图文发布，优先选择
暴露 API 或全局函数的平台
，而非纯 SPA 的编辑器。
