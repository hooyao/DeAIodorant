# CR-001 Generation Chain Audit

Audit date: 2026-09-14  
Audit version: `compact-refiner-generation-chain-audit-1.0`  
Scope: three originals and corresponding edits in reader preview 1  
Method: local artifact inspection and deterministic identity reconstruction  
New API requests: 0  
Training performed: none

## Finding and scope correction

All three originals displayed in the preview exactly match the final answer
strings retained by the CR-001 OpenRouter client. Their identities match from
the API result cache through the draft, unchanged candidate, blinded review
input, preview key, and actual Markdown presentation. The inspected local
chain contains no assistant rewrite between the source answer and the displayed
original. Assistant edits are the other, separately identified side of each pair.

The source tasks were nevertheless strongly shaped upstream: an assistant had
already supplied compact Chinese prose containing the complete facts, audiences,
voices, and directions for clear presentation. The preview contains two short
practical instructions and one public notice, all generated by the same Qwen
model and provider. It does not test ordinary full media articles.

During this audit the maintainer clarified that the product inputs are real
media articles, including already acquired material such as InfoQ. This
clarification governs next-step interpretation. These synthetic fixtures are
engineering controls for data handling and preservation checks. They are not
representative product evaluation inputs. A newly prompted synthetic full-article
batch would not correct that mismatch and is not recommended as the next main
experiment. No such batch was generated by this audit. No media corpus was
inspected or modified in this subtask.

The maintainer's observation, preserved as qualitative feedback rather than an
authorship label, is: "这3租都没有明显的的ai臭味". It applies to the displayed pairs
after comparison, not an independent baseline assessment. It does not establish
that actual media articles lack the target problem. Pair 1 also retains the
unresolved human concern about content differences. This audit does not revise
any feedback or promote any pair to training eligibility.

## Frozen code and provenance limits

The source driver `experiments/compact_refiner_run.py` stores `result["text"]`
as `draft_text`, hashes that exact string, and creates the unchanged candidate.
The frozen client's `_perform_attempt` obtains `choices[0].message.content`,
validates it, and returns that string. `strip()` tests nonemptiness only; it
does not transform the stored answer. No normalization, compression, style
cleanup, or assistant call occurs on this successful path. The separate source
recovery driver also uses direct assignment, but these three receipts belong
to initial `generate:` calls and require no recovery inference.

The current draft template, editor template, source driver, fixture, records
module, and frozen model catalog all match their initial manifest hashes.
Their archived copies match as well. Materialized briefs and the source run
manifest match the dataset manifest. The current draft file exactly equals its
archived snapshot.

The current `src/deaiodorant/refine/openrouter.py` differs from the source-run
freeze due to subsequent documented Retry-After maintenance. The audit used
the preserved CR-001 version under
`feature_runs/compact_refiner/cr001-code-snapshot/`, which matches the frozen
hash `05c368f61d9954dbc4eb331a02c83c072b5aded6401bcc1f50be9dbbb0a7333a`.
See [the maintenance note](../client-maintenance-2026-09-14.md). This accounted
code change is not evidence that an earlier answer was rewritten.

The source template hash is
`98bea5accc5358f50bea08df893bcdad86d85adf6cbd6bb8941c52d10ba7d9e4`; the editor
template hash is
`04c3fc6b4e800d874eaff974bb462829a125801c1e0fb7acedfeb272cacc77a0`. They were
not mixed. The edited side traces through `teacher_input_key.json`,
`teacher_inputs.jsonl`, and `teacher_proposals.jsonl`: `edit-05`, `edit-08`,
and `edit-13`. Those stored prompts exactly match the editor template rendered
on the originals, and the proposals exactly match the displayed edited sides.
They are labeled `model_assisted_agent`, not human edits. No external
OpenRouter receipt or provider-attested checkpoint is attached to those agent
proposals, so the local records support describing them as assistant proposals.

The client deliberately does not retain raw HTTP bodies, authorization headers,
or reasoning content. The exact source request is reconstructed, not recovered
from a raw request-body file. The cache, code, hashes, and receipts are mutually
consistent local evidence, not signed independent attestation of remote
execution. Within that limit, the claim that the originals were direct API
final answers is supported.

The fixture author is documented as assistant subagent `development_briefs`
in [the fixture construction note](../briefs-v1-notes.md). Actual rows confirm
constructed origin and rights, and their canonical hashes reproduce the
materialized brief identities. There is no independently verifiable authoring
session receipt for that upstream step in these files. This audit verifies
frozen input identity and content, not independent human fact authorship.

## Upstream shaping and selection

The actual fact packets are fluent connected Chinese prose. They already supply
dependencies, order, qualifications, and exceptions; they are not unstructured
source evidence. The model expands and rephrases substantial assistant-authored
content before any explicitly named editing stage.

| Brief | Packet code points / CJK characters | Draft code points / CJK characters | Supplied voice |
|---|---:|---:|---|
| `cr001-08` | 245 / 207 | 380 / 325 | Direct and cooperative, preserving dependencies |
| `cr001-12` | 227 / 196 | 376 / 330 | Inviting and precise, with respect for participant choice |
| `cr001-20` | 256 / 203 | 366 / 296 | Considerate and straightforward, with directions stated explicitly |

Code points include punctuation, numbers, and paragraph breaks; CJK counts use
U+3400-U+4DBF and U+4E00-U+9FFF. The request was 300-600 Chinese characters.
These are short passages, with one containing only 296 CJK characters. They
cannot evaluate sustained article-level repetition or development.

The tasks also request intelligible dependencies and responsibilities, clear
recording instructions and measurement limits, or explicit directions and
reopening conditions. Those legitimate instructions already target clarity and
relations that later edits might otherwise improve. The shared contract
requires all supplied facts and prohibits outside details, citations, and
personal experiences, making preservation the dominant constructed challenge.
It additionally mentions authorship, AI style, editing, and evaluation, which
unnecessarily reveals the subject of the study to the source model.

The preview was selected after candidate review for two clearer edits and one
smaller edit. It contains neither the larger batch's full genre mix nor both
source models. These observations identify restrictions and selection, not a
causal demonstration that prompts produced the user's no-obvious-smell judgment.

For the real-media route, the correction is to use the acquired article as the
original, retaining its stable source ID, canonical URL, timestamps, content
hash, and documented extraction history. Any assistant summary, fact packet,
polishing pass, or model reconstruction must remain separate from the original.
Read-only normalization should be explicit and reproducible. Whole-article
context should survive any selected excerpt. Article identity and source-only
review should be frozen before creating variants; model judgments remain
triage measurements, not human confirmation of the target smell. These are
scope recommendations only: this audit did not inspect or change media data.

## Verification procedure

A read-only Python script was executed from the repository root via PowerShell
standard input. It used `hashlib.sha256` on UTF-8 text and on file bytes, JSON
serialization with `ensure_ascii=False`, sorted keys, compact separators, and
single-pass substitution matching the frozen renderer. The checks were:

1. Match preview file bytes to its frozen key; resolve each review and draft ID.
2. Parse all six displayed blocks and match their text hashes to A/B key hashes.
3. Match original strings across review input, draft, unchanged candidate, and
   API cache; match the complete cache metadata object to draft metadata.
4. Resolve each ledger transaction; require a finished transaction and exactly
   one successful attempt for each audited source request.
5. Re-render each source prompt; reconstruct canonical messages and POST request
   identity; compare all three hashes against receipt and ledger values.
6. Re-render each selected assistant editor prompt; verify teacher-input keys,
   proposal inputs, and candidate output identity.
7. Match the per-brief fact and canonical fixture hashes; compare initial
   manifest, dataset manifest, frozen source files, and archived copies.

All text, prompt, request, and relevant frozen-artifact checks passed, with the
explicitly accounted current client-code difference. The exact reconstructed
source prompts are preserved below to make upstream shaping directly inspectable.
No credentials, raw authorization, old sealed reserve, or final-test input was
read. No source, candidate, prompt, key, or feedback file was changed. The only
new artifact owned by this subtask is this audit report.
