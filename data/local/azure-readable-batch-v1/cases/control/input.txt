# Microduck 机器鸭：硬件配置、购买方式与 DIY 成本

8月27日，Hugging Face（HF）旗下的 Pollen Robotics 开售 Microduck。这款机器鸭高25厘米，售价399美元，约合2680元。它配有仿真环境、训练代码和 SDK，可以用于学习强化学习（RL）、测试动作策略和开展机器人教学。

原文转述 HF 联合创始人 Thomas Wolf 在 X 上公布的数据，称“首日 4 秒卖出一台”，24小时订单金额超过260万美元，按单价折算约6500台。文中没有说明“4 秒卖出一台”的统计口径。国内博主“陈大叔”质疑这些数据无法得到第三方验证，目前销售额仍只有官方口径。

开售后的讨论也很多：B站相关视频一天获得1.7万播放，小红书头部笔记有1332个赞、1627次收藏，知乎两天出现十几个相关问题，微博甚至讨论起“瑞芯微概念股”。B站视频的收藏数也超过了点赞数。当时，英伟达拟以约129亿美元收购 Hugging Face 的消息仍在传播。销量数字和讨论热度，都不能替代对产品用途的判断。

## 硬件与软件

Microduck 重780克，有四种配色。15个电机分布在双腿、颈部和头部，鸭喙可以活动，也能充当小夹爪，叼起接近自身重量的物品。传感器包括广角摄像头、8×8 ToF 激光雷达、两个 IMU，以及分别位于头部和喙部的两根 NFC 天线。每台机器首次开机时会生成独特的声线，之后终身绑定。

它使用可更换的 NP-F550 电池，续航约1小时。默认包装包含一个游戏手柄和一块电池；额外电池包、轮滑包需要另购。长时间做实验，需要多备电池或考虑持续供电。

机载计算由国产瑞芯微 RK3566 核心板承担，具体型号为 Firefly ROC-RK3566-PC，配置是四核 A55、1GB 内存和32GB 存储。它没有使用 Jetson。

一位开发者记录了动作策略的训练和部署过程：先在英伟达 GPU 上，用 mjlab、MuJoCo Warp 和 PPO 训练走路、起身等动作，约1～2小时收敛；再导出 ONNX 文件，部署到机载核心板。开发者测得的控制频率为50Hz，即每20ms执行一个控制 tick，15022个 tick 中漏了3个。这份记录展示了训练与实际运行对硬件的不同要求，具体数据来自该开发者的测试。

训练和部署还需要注意软件版本。这位开发者使用的板载 ONNX Runtime 为1.20.1，策略要求1.23.x或更高版本，结果机器鸭未能站起来。修改训练流程时，要核对相关组件的版本，确认导出的策略与机载软件兼容。

软件仓库 [pollen-robotics/microduck](https://github.com/pollen-robotics/microduck) 已开放仿真环境、SDK、训练代码和7种预训练行为：走路、坐立、下蹲、踢腿、抓取、轮滑和跌倒自起。硬件图纸尚未开放，官方 BOM 和结构件图纸也无法取得。因此，目前无法依据官方资料组装一台相同的 Microduck。希望自行制作机器鸭的用户，可以参考它的前身 Open Duck Mini。

## 购买条件与交付时间

官方原计划在2026年圣诞节前发货。订单增加后，官方表示“新订单无法承诺圣诞前发货”。当前预计等待4～6个月，按下单先后发货。

据社区反馈，官方不向中国大陆及港澳台邮寄，国内用户已经开始寻找代购或转让订单。8月30日，小红书出现一则代订帖，写着：“已订 2 台（奶白&紫色），带电池包和轮滑包，发货时间以官方为准”。这些配件是该订单加购的，不能据此认为399美元的标准配置包含电池包和轮滑包。

购买成本还包括代购或转运费用。部分早期订单正在被加价转让。原文提醒，转让买家不能默认售后、保修以及“最快圣诞发货”的承诺会随订单转让，需要向相关方核实。

对教学、实验和 RL 部署来说，成品的方便之处在于已有完整的 sim-to-real 流程，可以从仿真训练衔接到真机部署。HF 此前推出的 Reachy Mini 售价299美元，累计售出约1万台，应用商店中已有200多个社区 APP。Microduck 开售两天内，社区也出现了仿真跳舞和仿真倒立的策略视频，这些演示仍在仿真环境中。

原文作者看重这套配套软件，推荐有学习和教学需求的人购买。他认为，这是首款将仿真训练、真机部署与 SDK 整合到399美元价位的成品，在4000元内没有同等方便的替代品。这项比较没有详细的竞品资料支持。

## 自行制作 Open Duck Mini

Open Duck Mini 的发起人 Antoine Pirrone 也是 Microduck 的主创，商业版 Microduck 由这个开源项目发展而来。

Open Duck Mini V2 的官方60秒组装视频展示了3D打印件、树莓派和总线舵机的安装过程，最后整机通电行走。它高42厘米，比 Microduck 大，官方公布的零件成本不到400美元。

国内已经有相关教程。B站“灵犀机器人”团队从3月起发布了使用树莓派4B、3B+和 Zero 2W 的不同版本教程，也录制了处理启动后持续向前走问题的视频，还有本地运行 Gemma 4 的端侧大模型演示。另有开发者基于 Open Duck Mini 制作 EmoLo 情感步态项目，用同一份 RL 策略表现开心、疲惫等步态。该项目被 IEEE Spectrum 的 Video Friday 收录。

实际采购价格未必能达到官方公布的成本。评论区有人提醒，总线舵机单买很贵，拿不到渠道价就难以压低总价；上半年的内存涨价也推高了树莓派等板卡的价格，不能直接沿用去年的预算。原文作者曾另写文章讨论这次板卡涨价。

一位有华强北背景的网友估算：“自己采购一套手搓，不会低于 4000 元，比人家零售价都贵”。这份估算与官方所说的不到400美元，来自不同来源，原文没有提供可逐项比较的采购清单。作者认为，个人按零售价买散件难以获得整机批量采购的价格优势，因此不建议以省钱为目的 DIY。

对于已有3D打印机、闲置树莓派并愿意自己调试的人，Open Duck Mini V2 仍是可选方案。它有现成教程，原文作者还认为42厘米的较大机身更“耐折腾”。自行制作可以更自由地修改硬件，不必等待 Microduck 发货。

## 国产方案的进展

评论区有一条高赞留言：“坐等华强北发力”。Microduck 的硬件图纸没有公开，国内厂商无法直接按官方图纸复刻。原文作者判断，要做完全相同的硬件就需要逆向，成本也会更高。不过，这项判断没有具体的逆向成本估算支持。

小红书账号“桌面具身刘厂长”展示了正在开发的机器鸭，采用树莓派和飞特舵机，硬件架构与 Microduck 不同。该账号承诺“后续这套方案软硬件开源”，当时还没有在文中给出仓库地址或发布时间。

对于希望减少转运麻烦、降低入门成本的用户，如果这类方案能做到软硬件开放、国内发货和本地售后，就值得继续关注。它的最终价格、交付和售后仍需等待进一步信息。想买399元替代品的人，也可以关注这些独立方案；原文没有给出399元的售价或相应承诺。

## 选择建议

学习 AI、机器人或从事相关教学的人，如果需要一套完整的强化学习真机环境，并且能接受4～6个月的交付期，可以考虑订购 Microduck。原文作者认为，399美元的设备比用数千至上万元设备试错更容易负担。等待期间，可以先使用开源仓库的仿真环境训练，之后将策略部署到真机；上面的 Runtime 问题也说明，部署前仍要核对兼容性。

已有器材和 DIY 经验的人，可以从 Open Duck Mini V2 开始。预算应按当前采购渠道重新计算，也要安排装配和调试时间。

如果主要想要一只开箱就能陪伴互动的桌面宠物，建议等首批真机使用反馈和国内渠道稳定后再决定。Microduck 是用于运动与实验的开发平台，会有跌倒和调试的需要。原文将它形容为“为了动而生、随时准备摔倒”的开发平台。

后续可以留意官方是否开放中国区直邮或代理、国内项目何时发布开源仓库、HF 是否在量产压力下公布硬件文档，以及4～6个月的交付期会如何变化。社区策略库能否从跳舞、倒立等演示发展出实用技能，也会影响它的长期用途。

# Nuxt Test Utils v4：基于Vitest v4，重构mock机制并强化环境的初始化

Nuxt Test Utils 发布了 4.0.0 版本，该版本主要集成了 Vitest v4。本次更新将测试环境初始化逻辑迁移至 beforeAll，修复了模块级 mock 失效的问题；同时优化了 mockNuxtImport，实现更简洁的部分 mock 功能，并完善了注册接口的状态管理。该工具库依旧是 Nuxt 框架测试的核心库，衔接了单元测试与端到端测试。

Nuxt Test Utils发布了 4.0.0 版本，它是基于 Vue 的 Nuxt 框架的官方测试库，这是合并包生命周期中的第一个主版本发布。该版本于2026年2月7日发布，构建在单一的依赖要求之上，即 Vitest v4。相比之前要求的 Vitest v3 的版本，这次升级推动了很多重要的变化，包括测试环境初始化方式和 mock 应用方式的架构性转变。

4.0.0 版本最具影响力的改动是将 Nuxt 测试环境搭建从setupFiles迁移到了beforeAll钩子函数中。在旧版本中，执行时机的问题会导致vi.mock与mockNuxtImport无法可靠拦截中间件或插件内的组合式函数，这类组合函数常会在 mock 生效前就被执行。此次修改修复了仓库中长期存在的两个问题，均为用户反馈模块级 mock 被静默忽略的缺陷。将初始化逻辑延迟至beforeAll，可以确保 mock 注册完成后 Nuxt 才启动，让 mock 行为在整个测试套件中保持一致且可预测。

这一改动带来了一定的迁移成本。在describe代码块顶层调用 Nuxt 组合式函数，例如useRouter()、useNuxtApp()，将会抛出[nuxt] instance unavailable错误，因为此时测试环境尚未初始化。解决方案是将相关调用移入beforeAll中：

```text
describe('router test', () => {
 let router: ReturnType<typeof useRouter>
 beforeAll(() => {
 router = useRouter()
 })
})
```

第二项显著优化为mockNuxtImport，现在会将原始实现传入工厂函数。这让部分 mock 变得更加简洁：测试无需从零构建完整的 mock 对象，而是可以包装或扩展真实实现，再根据每条测试定制行为。

registerEndpoint工具也完成了两项针对性的修复。此前在测试间进行模块重置时，配置文件中注册的端点会丢失，该状态管理漏洞已被修复；同时，URL模式包含查询参数的端点可正常匹配了，解决了使用参数化 API 路径测试的一类故障。

依托 Vitest v4 的升级，mock 导出的规则会更加严格。此前，访问 mock 模块中工厂函数未显式返回的导出项，会静默返回undefined，而在 Vitest v4 中会直接抛出错误。推荐的修复方案是在工厂返回值中展开importOriginal，默认保留所有原始导出，仅覆盖测试需要的部分。

对等依赖的要求更加严格，happy-dom需要 20.0.11 及以上版本，jsdom需要 27.4.0 及以上版本，@jest/globals停止支持 30.0.0 以下版本，@cucumber/cucumber需要 11 及以上版本。锁定了这些工具版本的团队，需要在升级 Vitest v4 的同时更新这些依赖。

Nuxt Test Utils 在 Vue 测试生态中占据了独特地位。@vue/test-utils负责独立的组件级单元测试，Playwright、Cypress 覆盖了浏览器端到端的场景，而 Nuxt Test Utils 衔接了二者，它能够在测试环境中启动完整的 Nuxt 应用，执行服务端渲染校验，在完整的 Nuxt 插件与组合式函数上下文中挂载组件。

从 v3 进行迁移的团队可查阅Nuxt官方测试文档与4.0.0版本说明；此前使用已废弃的nuxt-vitest包的用户，可以在GitHub迁移问题中查看迁移步骤。

Nuxt Test Utils 是由 Nuxt 核心团队维护、Daniel Roe主导的开源库，基于 MIT 协议发布，每周npm的下载量超过47万次，广泛应用于 Nuxt 模块生态，为应用代码与模块开发者提供贴合框架的标准化测试支持。
