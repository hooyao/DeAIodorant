# 六案例工程对照的变体设计草案

版本：`cognitive-move-probe-design-1.0`。日期：2026-09-14。状态：`draft_for_root_review`。

本草案由当前环境的 Astra 子 Agent `/root/probe_design`设计，提交主 Agent 独立复核后才能冻结。设计者已阅读两篇完整正文、SMZDM 的 metadata.title、当前篇章动作协议和既有六案例记录；设计者不会参加后续盲标注。既有记录仅用于理解案例范围，不作为 gold。本文中的预期是设计假设，不是人类标签或标注答案。

## 条件构造与用途

每例包含原文、一个等义变体和一个含义变体，共 18 个条件。原文条件直接使用冻结来源，编辑列表为空；另外两种条件分别把候选 JSON 的 `equivalent_edits` 或 `changed_edits` 应用到同一原文，不能在等义变体上再叠加含义变体。正文其余 blocks 和标题保持来源内容；M01 仅改 metadata.title。M04 的待分析范围包含 b015、b016、b017，但两个候选均只动 b015。

这里只设计局部构造，不生成产品改写。完整文章是上下文，完整焦点 block 是待分析范围；标注者可以继续把核心动作、支持、回顾和其他上下文动作分开。不得因为变体改了文字，就要求所有八个语义字段一起变化。等义对照检验核心含义和关系能否保持，允许连接词、并列方式和节奏造成呈现差异。

候选依靠人工逐例构造，没有随机生成、阈值选择或外部模型调用。seed、温度及采样参数均不适用。设计提示版本为主 Agent 于 2026-09-14 下达的六案例有界对照任务及其两次范围澄清；可复现构造以 JSON 中的精确 `old`/`new` 为准。随机呈现、模型身份记录、评分规则和冻结由主 Agent 的实验协议另行管理。

## 操纵选择

| 案例 | 等义操作 | 含义操作 | 预期检查边界 |
|---|---|---|---|
| M01 | 买、搓、等 → 买、搓和等 | 三路承诺 → 买这一条路 | 议程范围变化；没有被反驳的 A。 |
| M02 | 不是 A，是 B → 不是 A，而是 B | 明确排除 Jetson → 是否另带 Jetson 未知 | 否定状态转为未决，RK3566 肯定信息仍保持。 |
| M03 | 核心不是 A，是 B → 核心不是 A，而是 B | 玩具不属重点核心 → 玩具和管道都属核心 | 价值重点集合变化，不声称原文否认两种用途能够共存。 |
| M04 | 估算不是实测 → 估算而不是实测 | 有华强北背景的网友 → 本文作者 | 引述归属变化；原有估算性质和两次推断保持。 |
| M05 | 如果 → 若 | 一个任务调用 30-60 次 → 60-90 次 | 仅为数量字段覆盖探针；核心解释应保持。 |
| M06 | 不是因为 A，而是因为 B → 不是因为 A，是因为 B | B 为明确原因 → B 为可能原因 | 首建事实仍独立肯定，因果连接的确定性降低。 |

M02 的初始设想曾是把漏 tick 数从 3 改为 30。主 Agent 指出，只改例证数字容易与合理的标注压缩混淆，因此最终候选改成焦点命题的否定确定性。初始设想未作为条件写入 JSON，也未用于标注或结果选择。

M05 保留数字操作，因为对核心缓存关系做否定、跨调用范围或必要条件改动，都容易与段内“保存以避免重算”、随后缓存收益及全文架构形成第二个明显冲突，或只显化原文已有解释。没有为凑齐六个强操纵而采用这些方案。若标注未覆盖任务次数，不应计为核心动作失败；若标注明确报告次数却仍使用旧值，才可记录该数量字段未随输入更新。它不能与其他案例直接合并成六次同强度的核心语义成功或失败。

## 全文语境与主要不确定性

1. **M01 的范围。** 标题只承诺买，正文仍有买、搓、等。它新增标题与正文覆盖范围不完全对应这一构造混杂，但不是自动的承诺矛盾：标题可能先突出买，正文再提供其他路线。范围识别与结构评价必须分开；如果复核认为“买”可统摄整篇决策，也应保留分歧。

2. **M02 的否定与设备范围。** 原文可能只在说主要控制板，新变体询问是否另带 Jetson，因而涉及主要平台与全部设备清单的张力。段末“实机真不靠”本有范围歧义；若复核将其理解为明确排除任意机载高算力设备，新变体与它产生上下文张力。这一风险不能隐藏。未知绝不能标成肯定双平台。

3. **M03 的价值重点。** 原文已有“核心”限定，玩具与学习管道可以共存。含义操作增加玩具作为核心价值的地位，不是在修复一个已经证实的逻辑排斥。新变体也不声称两项价值权重相等。b027 的非桌宠提醒保留，桌宠与玩具是否被读作同一范围可能形成分歧。

4. **M04 的归属。** 换掉说话者时也撤去该网友的华强北背景提示；因此归属和来源可信度姿态可能一起变化。引号里的内容及后续估算限定保持。作者自引估算在语法上可解释，但会比外部引述更刻意。b013 的前身成本、b026 的已有设备和 b017 的商业规模迁移仍是原文已有分析难点。

5. **M05 的字段覆盖。** 60-90 次是一个任务的例子；b002 的 30 到 60 次为标准任务的平均区间，两者没有直接矛盾。合理省略这个例证数字不构成语义识别失败，也不要求新增纠正动作或被否定的 A。

6. **M06 的情态作用域。** 没采用更短的“可能因为”，因为它可能连带使“苹果第一个建立”也变成未确认事实。最终将首建主张独立肯定，再说“这可能是前述结果的原因”。句界和显式回指也随之改变，可能影响呈现；“这”仍可能被读成供给体系本身而非率先建立这件事，主 Agent 须复核首建顺序在因果解释中的地位。b057 的一般规律和 b059-b064 的类比、未来条件全部保留；这些上下文不能抹掉焦点句明确增加的可能性。

等义判断中最需复核的是 M03：增加“而”不改变否定、核心范围或被肯定的管道，但可能更突出对比姿态。M06 删除“而”保留因果替换关系，连接强度和口吻可能改变。M01 与 M05 是较弱的表面改动，其通过只说明非常局部的稳定性，不能支持广泛的释义 invariance。

这批数据来自两篇已暴露文章的六个开发案例。构造输入不是新的真实强例，设计者预期不是独立参考答案，模型对照结果也不是读者收益、因果验证、泛化率或 reward 验证。
