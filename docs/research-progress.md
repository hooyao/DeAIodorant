时间比较与读者评价中最强且可解释的交集，是形如

- 后期减前期的稳健效应：1.51；
- 时间比较的置换检验 p 值：0.033；

## 关系支持探测结果

首次尝试对“所声称的篇章关系是否有实际支持”进行建模时，提取了对比、因果、推论、澄清和强调实例。它使用依存角色、实体、谓词、否定、冻结的反义词集合、比较词、具体内容和抽象外壳内容，比较关系左右两侧的命题。它明确保留了 `indeterminate` 判定。

该探测在全部分析范围内输出了 476 个实例：241 个无法判定，147 个有支持，88 个类型不匹配。它没有产生任何高置信度的无支持或冗余判定。

提出的问题评分未能奏效：

- 每 100 句的问题判定数，其稳健时间效应为 0.04，仅后期样本中的读者评分 Spearman rho 为 0.06；
- 问题判定比例的稳健时间效应为 -0.03，与读者评分的 rho 为 0.00；
- 在第二轮 10 处修订中，该比例仅在两处下降，七处保持不变；
- 没有任何关系支持特征通过多重检验校正。

该规则正确识别出读者在多工具段落中指出的 `相反`，判定其为被误标为对比的详述关系。它也错误地将真实的 7:00 与 7:31 之间的时间对比，以及人工监控与 LLM 监控这两种替代方案，标为不匹配。若干读者不喜欢的 `真正` 框架，仅因后面跟着一个具体分句就被标为有支持。

归一化的宽泛对比密度与读者评分的 rho 为 0.51，但基本没有时间效应（0.06）；强调密度则具有稳定的时间效应 1.34，但与读者评分的 rho 较弱，为 0.17。这进一步说明，有必要将特定的完整否定对比构式与宽泛连接词分开处理。

弃用 v0.1 问题评分。仅保留其提取的实例和原因代码作为审计材料。失败在于语义和结构，而不是可以针对同一小批评分调参解决的阈值问题。

## 离群值政策与当前局限

## OpenRouter 结构化输出修正

此前 MiMo-V2.5 和 Hy3 的冒烟测试失败属于接口假阴性。
旧请求发送了本地服务器专用的
`chat_template_kwargs.enable_thinking=false` 字段，且只允许 320 个输出
token。直接复现表明，两个模型几乎将
全部额度用于推理，返回 `finish_reason=length`，且未输出
任何回答内容。

使用 OpenRouter 的显式推理控制并提供充足预算后，
MiMo-V2.5、MiMo-V2.5-Pro、Hy3、Hy4 Preview、
GLM 5.3 Flash、DeepSeek V4 Flash 0731、Qwen3.8 Flash、Qwen3.8 Max 和 Qwen3.8
2.4T-A95B 均生成了符合 schema 的有效回答。Hy4 最初返回了文档中已说明的上游共享池 429，
随后重试成功。这证明的是接口兼容性，而非
任务准确率。

分诊客户端现在将推理模式和 token 预算纳入缓存
标识和清单，提取字符串形式及内容分块形式的回答，并保留
不含敏感信息的结束、内容、推理和 token 诊断信息。

随后，在固定的 12 篇、五来源文档面板上，七个当前模型运行了相同的来源与价值 prompt。DeepSeek、MiMo、Hy3、GLM 5.3 Flash、Qwen3.8 Max 和 Qwen3.8 2.4T-A95B 均完成全部 24 次调用。Hy4 仅完成一次，另 23 次受到上游共享池限流。面板没有人工 gold，不能据此排名准确率。

因此，下一采集批次冻结三模型 fail-closed 策略：DeepSeek 和 GLM 筛查每个确定性候选，Qwen3.8 Max 只复核两者暂时高置信度一致的候选。最终准入要求三个模型均高置信度一致。这样使用了更大的当前模型，同时避免将最昂贵端点用于已被前两项测量排除的候选。

## 无边界名词链探测

协议 `nominal-chain-integration-probe-0.2` 替代了中止的全文操作尝试。版本 0.1 没有写出候选结果：由于代码和 DOM 片段只在解析后过滤，一篇 1,501 行教程使 Stanza 长时间运行。版本 0.2 将既有、不依赖内容的完整段落筛选冻结到解析之前，名词链阈值全部不变。

## 边界竞争实验设计

协议 `boundary-competition-development-1.0` 将读者定位的分割观察转为分阶段、可证伪的实验，不升级已被否决的 UD 候选规则。阶段 0 必须实现明确的词汇向量，包括分词路径熵、最优与次优路径差、间隙边界后验概率、歧义间隙数和到中心词的未消歧距离。版本 1.0 中，branching entropy、accessor variety、分词器分歧、专名或技术锚点仅作诊断，不作准入规则。

对后时期池排序之前，必须完成外部百分位截点校准并记录 hash。必须无短语专属例外地定位读者示例。读者阶段还要求从 16 篇不同且未暴露的后时期文章中，获得八个高竞争段落和八个匹配的低竞争段落，至少覆盖三个来源，每层至少两种体裁。30 篇 validation reserve 保持未打开。若不能组成全部八个匹配区组，实验停止；不得为凑批次放宽阈值。

每个选中段落应用相同的仅调整边界的结构拆解算子。编辑者不知道高低层及展示侧。16 项干预在分层与场次内平衡，加一个相同文本诊断和一个稍后的镜像重复，共 18 个任务，seed 为 `2026083101`。读者仍只回答哪个版本更愿意继续阅读，并可明确选择无差异。

开发决策要求工具、原意保留及操作检查通过；高竞争层至少六个明确偏好回答，其中修订偏好至少 75%；高层净偏好至少 0.50，高减低筛选器差至少 0.50。低层有益但缺少层间差时，即使算子仍有研究价值，也否决筛选器。可选评论不影响任何门槛。

Exact-binomial 敏感性分析说明这项 16 段实验不能称作验证。没有平局时，真实修订偏好概率为 0.70，在双侧 alpha 0.05 下达到 80% power 需 49 次明确比较；0.75 需 30 次，0.80 需 20 次。无论达到哪种次数，同一读者的重复结果都不能产生独立读者复现。后续验证设计必须使用多名读者、held-out 段落，并基于读者与材料交叉模型进行模拟。

随后阶段 0 使用 SUBTLEX-CH 和 150 条公开 Beijing Sentence Corpus 句子校准冻结词汇格。在不打开 validation reserve 的情况下给全部 87 个旧结构候选评分。高竞争为零；23 篇文章中的 36 个实例进入低层，51 个居中或未评分。七个通过熵和路径差门槛，但只有一个有两个歧义字间隙，没有候选达到要求的六字符未消歧距离；最大值为四，因此没有高低匹配边。

读者示例自身的歧义间隙为零、未消歧距离为二、熵百分位 0.669、路径差百分位 0.346。最优 SUBTLEX 路径为 `原生 / 时代 / 全新 / 算 / 力 / 服务`；记录词典领域陈旧导致的 `算力` 拆分，不在结果后修正。否决 `boundary_competition_v1`，不创建 Project 8，将当前假设重新解释为词级修饰附着或短语括分竞争。

## 词级修饰语括分探测

有界的 OpenAlex、Crossref 和 Semantic Scholar 检索找到了基于依存概率、词语关联、术语证据、隐含关系释义的英文名词复合词方法，以及中文词频、语义透明度和词结构的相关研究。已记录检索式、部分结果深度限制、OpenAlex 预算耗尽、Semantic Scholar 429 错误及六次精确 DOI 摘要核验。从英文名词复合词迁移到中文技术修饰堆叠仍是未经验证的类比。

协议 `modifier-bracketing-probe-0.2` 穷举 Stanza 实词 token 的所有右中心二叉树。使用 1,393 个完整段落的有序词对概率评分附着，排除候选所在的整篇文章。专名、数字、ASCII 术语、引号标题、token 熟悉度、精确序列 termhood 和跨来源支持均保留为独立竞争变量。

版本 0.1 在操作上无效，因为百分位 midrank 使并列最小路径差无法通过门槛。版本 0.2 在重跑前冻结 `1e-12` 数值零容差和 nearest-rank 值截点；未改变实质阈值或输入。之后两次独立 `gx10` 运行得到逐字节一致的产物。

读者示例通过单例门槛：归一化树熵 0.822、最优与次优差为零、熟悉 token 比例 0.857、弱附着四处。多来源门槛失败。34 个可评分候选中，七个通过熵门槛，26 个通过路径差，17 个通过熟悉度，27 个通过弱附着。五个同时通过熵和路径差，但均未同时通过熟悉度。这五个是名称或稀疏技术字符串，无法构成独立的熟悉词修饰堆叠集合。

否决当前词级树熵向量作为干预筛选器。附着竞争仅保留为一个读者示例的局部解释。隐含语义关系欠明确是更强的下一候选，但本结果不能证明它。任何新的熟悉词弱关系测量都必须冻结，并在独立语料上检验；结果后不得重新筛选已暴露的 87 个候选。不准备 Project 8。

## 下一步研究

不构建产品界面、不训练通用分类器，也不要求读者继续已停止的筛查。第四轮干预已完成：五次偏好修订版、四次偏好原版、一次无差异。尽管原版展示位置平衡，全部九个明确回答都选 B 侧，因此处理汇总受到位置混杂，不能验证算子。

读者报告了另一种困难：每个词都熟悉，但整合起来难以理解。结果后的确定性探测得到混合证据：10 对修订版的虚实词比全部下降，六对的每分句中心词实词量上升，但句长、树深和长依存通常下降。没有定义或验证任何复合负担分数。

命题解压缩干预已完成。相同文本和镜像控制均通过，因此六个处理结果可解释为开发证据。三次偏好修订版、三次偏好原版，无平局。不升级通用拆句或命题解压缩。

一个被偏好的修订版仍保留了读者定位的问题：`AI 原生时代全新的
算力服务需求`。中心名词 `需求` 出现在长修饰串之后，泛化的时代和新颖性修饰也没有说明需求新在哪里。无模型词汇探测能定位原版与修订版。

第一批 50 篇交接在项目 5 至 7 后，只剩 21 篇可用于开发。公开采集量子位、雷锋网和华为新增 319 条原始记录。经过确定性翻译与重复排除、当前模型来源一致、双 prompt 价值筛查、跨模型价值一致、分层置信度及传播可见度筛选，形成新的 97 篇、五来源交接。冻结验证器报告零错误、零警告。

模型选择依据实际捕获的 OpenRouter 周使用量排名，不凭记忆中的热度。排除了身份不透明的 Ox Alpha。排名第二的 DeepSeek V4 Flash 0731 通过任务专用的结构化输出 smoke test。MiMo-V2.5 和 Hy3 看似返回空回答，因此未批量运行。后续审查复现出空回答原因为 token budget 耗尽：不支持的 disable-thinking 字段未关闭 reasoning，reasoning 用完全部 320 个 completion token。在更正 OpenRouter 参数后，两模型均返回有效结构化回答。v2 交接保留原有 Qwen3.8-27B 加 DeepSeek 测量身份，接口修正不追溯改变它。在该历史阶段，API key 未持久化或复制到 `gx10`；后续维护者已授权在被忽略的 `.env` 中保存，凭据仍不得提交。

新段落分析前冻结角色划分：67 篇开发文章、30 篇 validation reserve。保留区尚未用于特征发现，且没有多名读者就不能支持验证。

对独立的 119 篇交接应用同一冻结规则，得到 38 个宽泛中心词延迟候选，严格低锚点抽象堆叠为零。严格模式未复现。该交接只有前时期和过渡期文章，也没有与后时期池匹配，因此这个零不能估计时间效应。

仅对扩展交接的 development 分区应用规则，在 14 篇文章中得到 23 个宽泛候选，严格实例再次为零。未阅读 validation reserve。不得依据这些结果放宽定义，也不得用宽泛假阳性候选创建项目 8。

更宽的冻结模式清点也没有形成一致的筛选器。新的 93 篇交接通过固定的当前模型及完整性门槛，且与 v2 两个分区和所有既有读者产物分离。完整的冻结规则扫描再次发现严格中心词延迟实例为零，也没有新的统一算子。全部 93 篇都已暴露于特征发现，不再是读者验证材料。

当前不再准备基于边界或括分的读者批次。两个筛选器都未通过冻结语料门槛。单个读者示例与词级附着竞争相容，但开发语料中的熟悉词候选没有呈现同样树熵模式。下一候选是隐含语义关系欠明确：熟悉词并置，却不说明主张之间如何关联。采集并打开新的独立后时期发现语料之前，必须先冻结确定性的熟悉词弱关系规则。不得重新筛选已暴露的 87 个候选，也不得打开 validation reserve。

更宽的 Stanza 名词链探测并未取消这一要求。其频次门槛通过，但候选并不是同一种结构。新协议使用独立冻结的词汇熟悉度和分词边界向量，阶段 0 失败。仍禁止针对这 87 个候选事后建立词汇黑名单；没有创建 Project 8。

这仍是单读者开发工作。扩展语料现在保留了覆盖三个来源、三种体裁和三个主题分层的独立文档保留区。Held-out validation 仍要求多名独立读者，并在结果前冻结算子与分析计划。

不得用同样的 10 个评分调整已被否决的 relation-support 分数。进一步研究真正的关系支撑，需要更窄、可形式化检验的模式，或独立专家 span 标注。不应要求读者提供这些语言学标签。

同时，在更大的匹配语料到位后，对它运行同样的图特征。解释时间效应前，匹配来源、主题、体裁、篇幅及传播可见度。

当前 119 篇交接不是这种匹配语料：没有后时期文章，机器之心的传播可见度也未核验。它只扩大发现材料。

第三轮干预使用了这一已暴露于发现的交接中的 12 个过渡期段落。它扩展体裁覆盖，但属于开发证据，不是 held-out validation。其算子、段落、编辑、原意保留检查、任务顺序及 A/B 平衡均在结果前冻结。

结果为四次修订胜出、一次原版胜出、七次平局或都不偏好。研究摘要为两胜两平；技术实践为一胜、一次原版胜、两平；行业报道为一胜三平。读者表示几乎所有配对差别很小，因为原段落没有明显臭味。只有一条可选评论指出具体标记：`换句话说`。

因此，第三轮诊断出的是选样问题，不能据此加大改写强度。仅靠标记存在和体裁平衡，无法识别基线阻力足够高、能从编辑受益的段落。后续开发选样应使用独立的低负担读者基线筛查，并将被筛查材料排除出 held-out validation。参见 `experiments/refinement-pairs-v3.md` 和 `data/annotations/refinement-pairwise-v3.json`。
