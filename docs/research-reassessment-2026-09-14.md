# 传统 NLP 研究路线的重新评估

日期：2026-09-14。状态：回顾性的方法批评与方向建议，不是冻结实验或新的实证验证。

维护者澄清，问题在于无法通过传统 NLP 特征和统计，验证感知到的公式化写作。把问题替换成 LLM 臭味评判器或一般改写产品并不能解决它。下方建议保留传统 NLP 测量路线，以读者体验作为产品结果。

## 主要发现

已有工作否定了若干具体代理指标，尚未证明底层读者体验不存在，或超出了传统 NLP 的处理能力。仍有三个问题纠缠在一起：目标 construct 不稳定、测量经常捕捉到其他现象，以及数据的推断能力十分有限。仅增加特征或未标注文章不能解决这些问题。

也有值得保留的正面证据：读者偏好部分保守编辑。但这些编辑同时改变了段落的多个方面，因此无法确定某个标记的因果贡献。

## 证据边界

本次复核检查了 commit `306e5e0ec1802da2c6f7a741d2ea557d4db04be9` 下的代码、受版本控制的 development 标注、实验报告，以及可用的本地 pilot／读者特征产物。

当时的 checkout 没有 `data/local/` 目录。涉及 97 篇和 93 篇交接数据及后续 parser 运行的结果，依据受版本控制的报告和实现核查，未独立重跑。没有打开 sealed test 或 validation reserve 文本，没有改变历史标注、阈值、特征配置或结果，也没有使用付费推理。

## 为什么统计未能确立臭味特征

### 1. 可观察结果与拟研究现象出现偏离

最初的读者量表把流畅度与继续阅读意愿放在一起。评论提到装饰性表达、空洞扩展、语法、指代、逻辑推进、信息价值低和特定主题的理解难度。这些体验可以并存，但未必具有相同的特征方向。

第一次干预已体现这种区分。第一组被认为原文的公式化标记更明显，但改写的语法完整性更差。其他受到偏好的改写又被批评语气冷淡。单一偏好分数无法识别哪个维度导致了选择。

后续研究从对比式重构转向整合负担、中心词后置、分词竞争和依附歧义。这些语言学假设都有合理性，但每次转换都改变了 construct。读者描述短语难以切分是一项观察，不能独立确立某种心理语言学分词机制。

应区分三个测量：

- 感知到的公式化程度：风格诊断，需要具体正反例，绝不能作为作者身份标签；
- 理解难度：受术语、先验知识、指代和上下文缺失影响；
- 继续阅读意愿：主要产品结果，也受兴趣、信息价值和表达语气影响。

如果即便提供锚定样例，公式化感知仍无法重复，就尚无稳定的总体 construct 可供回归。可复现的个人偏好仍是合理但更窄的目标。

### 2. 早期读者分析具有严重的分辨率限制

直接根据 `data/annotations/reader-friction-v1.json` 和本地 `feature_runs/reader-friction-v1/` 输出核实：

| 测量量 | 观察值 |
|---|---:|
| 后期已评分段落 | 8 |
| 不同的后期文档 | 7 |
| 读者 | 1 |
| 后期观察到的评分类别大小 | 5 和 3 |
| 标签的不同排列数 | 56 |
| 本次读者分析检验的非恒定特征 | 138 |
| 报告的最小精确双侧 p-value | 0.035714 |
| 报告的最小 BH q-value | 0.951128 |

标签只有 `8! / (5! * 3!) = 56` 种排列，因此精确 p-value 的分辨率为 `1/56`。对于 rank 无并列的特征，最极端双侧排列的 p-value 为 `2/56 = 0.035714`。特征中的 ties 会改变可达到的尾部概率，因此后一界限并不普适。

在 138 次检验、false discovery rate 为 0.05 时，第一个 BH cutoff 是 `0.05/138 = 0.000362`。如果足够多的 p-value 都较小，BH 仍可能拒绝，并非数学上不可能。但孤立的强候选几乎不可能在这种设计中通过。增加 Monte Carlo 排列次数，不能给 56 种唯一排列增加独立信息。

代码还按段落进行排列和留一法，而非按完整文档。两个后期段落来自同一文档，使不受约束的 exchangeability 成为额外假设。修正这种依赖也不会创造更多证据。同一读者重复完成任务，不能视为独立读者重复。

适当结论是识别不足，不能据此证明无效应。保留多重比较校正，改变前瞻实验设计。

### 3. 时间对比只是研究读者体验的间接途径

最初同来源时间比较使用 10 篇前期和 10 篇后期 InfoQ 文档、150 个稠密特征和 6,597 个稀疏模式。主题和体裁未匹配，至少一篇后期文章已知是译文。更大的 119 篇交接数据没有后期文章，无法补齐缺失的匹配主对比。

标点变化可能只是编辑排版差异。读者不喜欢的构式可能两个时期都有，也可能两期都罕见。时间可分性及其缺失都不能确立读者影响。最初最强的标点发现属于样本层面的分布差异，解释尚未解决，不是已验证臭味。

保留时间用于次要外部复现和 prevalence 研究。不要要求某个特征先随发布时间变化，才允许检验它能否定位可编辑的读者问题。

### 4. 特征经常测量了不同层级的组织方式

文档均值可能稀释短小但令人不适的 span。标记总数丢掉了对比是否必要、出现在何处，以及多个转折是否反复表达同一主张等信息。词汇重叠把解释性重述与空洞重复混在一起，也把词汇变化与真正的信息推进混在一起。

篇章支持探针体现了这种局限：它输出 241 个 indeterminate、147 个 supported 和 88 个 mismatch 判断，却没有 unsupported 或 redundant 判断。其自身审计发现，真实对比被误分为 elaboration。这是该测量的 construct validity 问题，不能证明篇章支持不重要。

同样，Huber 估计针对组内的典型位置，有助于检查污染敏感性；但罕见局部模式可能恰好位于被降低影响的尾部。这是可能的 estimand 错配，不能据此断言 Huber 权重造成了零结果。应保留原始与 robust 汇总，提前定义任何未来的尾部 estimand。

### 5. 严格候选门槛检验的是代理指标交集

词汇边界筛选器没有找到 high-stratum 样例，其字幕词表未按预期表示现代技术单位 `算力`。词级探针只对 87 个候选中的 34 个评分，没有一个同时满足 entropy、margin 和 familiarity 条件。

这些是冻结筛选器的有用失败，不能说明读者从不难以理解这类短语。稀疏的领域计数可能让模型不确定性看起来像依附歧义。多个阈值取交集，还可能在检验任何读者关联之前就消除整个采样支持集。

正确下一步是用 positive controls 和匹配反例校准测量，而非在同一批候选上降低失败的 cutoff。87 个候选的边界和未打开的 reserve 保持原样。

### 6. 采样可能消除了产品问题所需的变化

高价值、高传播可见度语料适合原来的时间研究目标，却未必代表用户想编辑的草稿。保守的价值筛选和多模型交集可能收窄表达范围；判断一致并不保证筛选无偏。这是合理的潜在选择机制，尚未被确认为这些失败的原因。

同文档筛查同样发现反差有限，一条评论认为两段都有明显臭味。按文档匹配可以控制有用的混杂因素，同时也可能消除感兴趣的风格变化。跨文档比较恢复变化，却又引入主题兴趣差异。

时间 prevalence 与编辑研究使用分开的、名称明确的数据集。保留语料准入要求，不要把范围更广的编辑 development 集静默改标为正式比较语料。受控合成扰动属于测量校准，不属于自然 prevalence 估计或 human gold。

### 7. 编辑证据未能隔离标记机制

第二轮有六次改写胜出和四次平局。操作同时移除引导框架、澄清论元、改变措辞和重组命题。结果支持继续研究这一编辑组合，不能确立单独删除 `不是...而是...`、标点或强调导致了收益。

第四轮全部偏好 B 的模式阻止了对编辑操作的解释。六组受控减压配对各有三次胜出。在这一小型 development 集中没有整体优势，但它并非证明减压从不有效的 equivalence test。

原意保留检查也需谨慎解释。在 `prepare_refinement_pairs_v2.py` 和 `prepare_integration_pairs_v1.py` 中，claim checks 验证所提供的支持字符串是否在原文与改写中出现。它们是有价值的审计支架，但不能在计算层面证明 entailment、主张完整或范围未变。编辑者的语义判断仍是测量的一部分。

## 值得检验的传统 NLP 方向

以下是候选，不是发现。先选一个方向，最多两个，不再建立庞大的特征集合。

| 方向 | 传统测量 | 可区分的预测 | 必要反例 |
|---|---|---|---|
| 引导框架重复，内容推进有限 | 固定段落窗口；修辞构式复现；TF-IDF 或 LSA 内容相似度；新增实体／行动／数量提及；预先指定交互，不能只看标记计数 | 后续单元增加的可恢复内容越少，重复框架越令人不适；任一单独成分都不足 | 有用回顾、连贯的技术术语重复，或引入真实备选项的对比 |
| 篇章顺序与指代连续性 | Entity-grid 转移、词汇链、提及距离、句间转移模式；比较实际顺序与受控排列 | 在 unigram 与标记总数不变时，表示能区分局部推进的断裂 | 合理的话题转换、章节边界，或上下文可解决的指代 |
| 超越主题词汇的公式复现 | 实体／数字 masking、功能词与 POS 构式序列、document-frequency dispersion、匹配体裁内的平滑 log-odds | 控制内容词汇后，重复框架仍可跨主题和来源观察 | 标准方法说明、法律模板，或有用的重复解释模式 |
| 局部集中与异质性 | 预先指定固定长度窗口、上分位数或事件覆盖汇总，以及来源／体裁交互 | 局部信号比文档均值更能预测段落内读者反应 | 篇幅影响、一段引文、代码或孤立的 parser 错误 |

第一个方向优先级最高，因为它把早期关于空洞扩展和刻意营造深刻感的评论，连接到显式交互。各成分都有局限：TF-IDF 相似不等于语义等价，新增实体不自动等于新增命题，熟悉事实仍可能有用。定义 composite score 之前，必须用反例检验这些局限。

第二个方向中，句子打乱是敏感性对照，不是自然劣质写作的模型，也不能证明读者受损。第三个方向中，无监督 cluster 或稀疏 regularized model 可以组织 development 观察，但目标必须是可观察写作模式或读者反应，绝不能是推断出的人类／AI 作者身份。报告预测表现时，词表、IDF、LSA 和特征选择均须在训练分区内部拟合。

## 信息更充分的下一项实验

### Development：确定测量行为

1. 已暴露的读者样例只用于透明的错误分析和初步 construct 描述。保留评论原文，分析者解释放在独立字段中。不得将它们重新评分为独立 validation，也不得从冻结的 87 个候选重新筛选。
2. 建立小型、新的 development 样本组，同时包含正例候选和难反例。24 篇不同文档的预算仅用于可行性检查，不是具有充分 statistical power 的验证样本。纳入流畅但公式化的文本、没有明显公式化但难读的技术文本、有用重复，以及推进清楚的文本。初始分层属于分析者假设。
3. 在小子集上，分别检查公式化感知、理解和继续阅读意愿的可重复性。有条件时使用独立读者，否则明确目标是一个读者的偏好。读者无需标注句法或推断作者身份。如果平局会掩盖差别，应区分两者都好和两者都差。
4. 在已声明的 development 集上，最多拟合与检查两个低维测量家族。选择 cutoff 前，先检查连续分布、覆盖率、false positives 和 negative controls。明确标为 development 时允许迭代，但不能把迭代当作确认。

### 冻结复现：检验具体机制

测量行为合理之后，冻结独立 protocol，采集独立评估文档。已有 reserve 继续保持未打开。

对框架／推进假设，在可行时比较同一底层段落的四种受控形式：原文、仅编辑框架、仅编辑推进、组合编辑。保留全部独有命题、必要对比、否定、不确定性、归属和语气。若不编造关系就无法编辑，则 abstain。不要假定每段都支持全部四种条件。

在读者间 counterbalance 条件，避免要求同一读者查看同一来源的所有版本。继续阅读意愿仍为主要产品结果，公式化程度作为诊断，原意保留作为独立门槛。估计特征是否能筛出对编辑有反应的样例，而不只是编辑者能否改善段落。

以文档和读者为采样单位。数据充分时，预先指定的 ordinal 或 pairwise mixed-effects 分析可以建模读者／项目差异；小型 pilot 则使用 clustered 描述估计和区间，不假装复杂模型会创造 statistical power。根据实际有意义的效应、平局以及读者／文档变化进行 simulation，确定评估规模，不使用最大的探索性相关。仅保留一至两个主要对比，并保留多重比较控制。

分别解释结果：

- 读者判断不可重复：修订或收窄 construct；
- 测量对照失败：在 development 数据上修订表示；
- 编辑有效但特征不能筛出收益：拒绝该筛选器；
- 测量有效但效应区间宽：证据不足；
- 窄区间排除了预先指定的有用收益：构成反对该具体特征／操作组合的证据；
- 偏好提高但原意保留失败：拒绝该编辑。

## 应停止什么、保留什么

停止在缺乏独立校准的情况下，把单个名词链样例延伸为越来越复杂的通用筛选器。停止向同样的八条评分添加数百个特征。停止把零候选、不显著检验和无效测量当作同一种负面结果。

保留冻结失败记录、来源 manifest、读者评论、可检查的编辑操作、确定性特征，以及 development 与 validation 的区分。这些都是有用基础设施。需要重新设计的是 construct 与实验，而非全面重写代码。

@'

import json
import math
from collections import Counter
from pathlib import Path

ratings = json.loads(Path('data/annotations/reader-friction-v1.json').read_text(encoding='utf-8'))['ratings']
post = [row for row in ratings if row['month'] >= '2025-07']
counts = Counter(row['rating'] for row in post)
arrangements = math.factorial(len(post))
for count in counts.values():
    arrangements //= math.factorial(count)
with Path('feature_runs/reader-friction-v1/feature_correlations_post.csv').open(encoding='utf-8', newline='') as handle:

    'documents': len({row['doc_id'] for row in post}),

    'label_arrangements': arrangements,
    'tested_features': len(rows),
    'minimum_p': min(float(row['exact_p_value']) for row in rows),
    'minimum_q': min(float(row['bh_q_value']) for row in rows),
    'first_bh_cutoff_at_0_05': 0.05 / len(rows),
