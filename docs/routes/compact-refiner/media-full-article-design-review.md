# 真实媒体全文开发设计复核

日期：2026-09-14。状态：独立设计建议；本文不报告候选生成、新人工结果或训练运行。

建议的 protocol 标识：`compact-refiner-real-media-full-article-1.0`。执行运行必须在生成候选前冻结具体来源 manifest、干预、请求和分析。仅有本文不等于已执行或确认性 protocol。

## 纠正后的任务与证据边界

维护者确认，目标是已从 InfoQ 采集的那类真实中文媒体写作：在保留信息价值和作者意图的前提下，提高读者继续读完整文章的意愿。目标包括空洞扩写、重复强调、装饰性框架，以及流畅句子之间支持不足的关系。某个表达是否有问题，取决于它在文章中的功能。

发布日期、已知生成器身份、NLP 特征和模型一致意见，都不能确立文档具有读者所指目标问题。本路线不识别作者身份，也不要求先有通用臭味分数，才能针对读者报告的问题测试具体编辑。

维护者对真实媒体的澄清取代此前[全文来源探测](full-article-source-probe.md)的生成来源范围。保留该提案和短构造 CR-001 材料作为历史记录。它们仍是有用工程案例，但不提供目标媒体分布。不要再次运行合成来源生成器，替代已有真实文章。

复用旧采集 provenance、人工评论、操作日志、意义保留检查、特征定义和失败选择器。复用不恢复已暂停的前后期发现计划。本次不检查封存预留集、已暴露翻译 final-test 输入或新 validation 文本。

历史[臭味目录](../../smell-catalog.md)已记录读者对 `相反`、`这样一来`、`它真正解决的` 等关系框架，以及未解决表达 `AI 原生时代全新的算力服务需求` 的异议。这些是有上下文反例的 development 线索，不授权到处删除这些字符串。通用展开和自动去标记已产生混合或失败证据。

## 最小有用 development 批次

从两篇不同、此前已暴露且有明确读者问题反馈的来源文章开始。使用已有反馈定位受影响片段。如果另一篇已暴露文章有明确无明显问题反馈且完整原文可用，可加作一个过度编辑对照。不生成替代品，也不为填满这个可选位置要求维护者筛新批次。

候选输出前冻结选样。优先精确可恢复来源和清楚的反馈到片段映射，不只追求看似强烈的例子。若合格问题文章超过两篇，用稳定文档 ID 与冻结 seed 的 hash 排序。记录每篇考虑过的文章及排除。文章的全部版本、节选、历史干预和未来衍生物放在同一 development 组。

旧人工评论确立的是特定历史抱怨，不是新的全文基线评分。在该来源上作新全文比较，可以确立对新编辑的个人 development 偏好，不能确立独立复现、总体收益、自然问题 prevalence 或 SFT 改善。

历史交接材料不可用是复现限制，不能据报告重建文本。允许时按正常采集路径恢复可访问来源，保留新时间戳和 hash，并与保存原文比较。变化后的来源是新版本。如果读者抱怨的段落无法对齐该版本，就不能声称目标覆盖已获读者确认。

## 编辑前的来源门槛

逐篇保留 canonical URL、来源与标题、发布和采集时间、正文 hash、提取版本、原始产物引用、历史任务 ID、反馈引用和暴露状态。原始正文不改。任何提取修复另存独立 hash 版本，并记录转换。

对照来源页面或已保存完整抓取审计完整性。检查开头结尾、章节顺序、段落、引述、列表、表格、代码块、链接、脚注、图锚点、图注和图片中的文字。导航或广告只可作为有记录的提取操作删除，且须在冻结可编辑文章前完成。正文看起来长，不证明完整。

两个读者版本中的图和其他资源保持相同位置。不凭想象重建缺图，不悄悄删除图注。记录缺失或不可访问资源。重要主张若依赖不可用视觉内容，该文章暂不能支持结论已解决的全文上下文比较；继续其他合格文章。纯文本抓取必须明确标明，不能悄悄变成完整来源。

翻译状态保持明确。已知翻译或编译外文文章仍排除于主要语料和主要媒体参照池之外。保留其历史标注为 development challenge 证据，不抹除或改标原创。原创不确定者不能悄悄进入主要语料。单独标记的诊断使用不修复语料资格，也不允许前后期结论。绝不使用已暴露翻译 final test 改进门槛。

分别记录私有研究、提供者处理、训练和再分发的使用权。公开可读不确立训练许可。训练权利未知时设 `training_eligible=false`；这不必阻止来源检查、本地准备或其他已授权私有诊断。明确来源限制仍有效。不发布完整第三方正文、不编 license，也不假定 API 授权改变文章权利。训练导出前解决实际用途与适用证据，不把未来前提变成当前 development 工作的一概审批请求。

## 候选输出前要冻结的三个原则

1. **从原文冻结目标和允许操作。** 每篇问题文章保存仅原文计划，包含历史抱怨、精确原文 offset、一个主要操作家族、一至三个目标片段、预期阅读收益、合理反例和必须保留的意义。使用足以测试抱怨的最小完整片段。保留必要对比和有信息的重复。看似模糊或无支持的主张仍是主张，不能只为使文章具体就删除或加强。
2. **给每个编辑者相同全文与有限权限。** 冻结低强度、目标片段、受众、现有作者风格、合法保护内容、输出 schema、模型或 agent provenance、尝试次数和预算。全文是上下文，只有计划片段可编辑。编辑输入不含偏好答案、私有复核结论和主张清单裁定。不能因首个候选令人失望就改 prompt 或请求另一个有效候选。修复是新候选版本和独立 development 结果。
3. **冻结失败、选择和报告规则。** 不修改输出合法。重放无效、越界编辑、截断、严重意义变化或保留未解决，都阻止候选进入读者对照。保留并计入失败。冻结合格对照如何进入材料包、全部计划文章及组如何保留在分母中。结果出现后不选择风格分数阈值或偏爱模型输出。

首批应锁定标题、章节标题、引述、引用、图、表、代码和章节顺序。有限例外须依据原文说明，并在生成前冻结。若表面问题要求新事实、解决真正来源歧义或改变已断言结论，将其归为本风格干预范围外。不编造缺失语义关系。

## 候选组与操作约定

逐篇保留 U，即精确原文。如果经核实的当前 endpoint 能在冻结成本与 context 限制内支持完整请求，用已有未微调 `qwen/qwen3.5-9b` prompt 基线作 P。记录请求与返回模型或 provider 身份及 revision 不确定。这复用了更有信息的已有小模型基线，不是最终 student 选择，也不证明 endpoint 与未来训练 checkpoint 相同。

仅在仅原文计划确定有用且在范围内的干预时，使用 T，即独立撰写的强助手提案。T 记为模型辅助，绝不是人工编辑或训练 gold。T 若使用迭代推理或人工式检查，披露其与 P 单次调用的区别；表现差异不能纯粹归因模型规模。

P 和 T 收到相同原文、合法上下文和冻结目标权限。无明确问题对照允许返回无操作，不强求象征性编辑数量。全文若超过模型实际请求限制，记录运行排除，不悄悄截成看似等价的任务。

编辑者返回结构化局部替换：基于精确原文、左闭右开的 Unicode code-point offset、`before`、`after`、操作类型和简短理由。从右向左应用非重叠操作，精确验证 `before`，确定性重建全文。保存操作列表、完整输出、hash、局部和完整 diff。无操作输出须按声明的 UTF-8 序列化逐字节复现 U。缺失、格式错或截断输出不是 keep 决策。

本运行检验具体有限修复能否在全文上下文中完成，尚不测试自主全文定位器。仅原文计划属于 development 指导；指导编辑成功，不证明小模型能独立找到相同问题。有值得进行的修复后，再用新版本实验单独测试定位。

## 意义保留与诊断复核

建立独立、仅原文的清单，覆盖命题、数量、单位、实体、引用、条件、范围、不确定性、否定、归属、所指和作者立场，包括目标片段外的相关上下文。事实主张记录为作者主张，不悄悄认证真值。另有事实缺陷不授权在风格评估中修内容。

运行确定性完整性检查并比较保护内容，再用完整原文和完整候选做候选身份盲态语义复核。双向检查丢失与新增，包括改变连接词导致的新隐含意义。数字和姓名精确保留，不证明条件或范围保留；CR-001 已有反例。记录 `pass`、`fail` 或 `uncertain`、证据片段、复核者身份和分歧。候选作者不能提供唯一接受判断。

对可供读者复核的候选，另问目标问题是解决、不变还是被新问题替代，以及编辑是否破坏后文指代或文章论证。这些是注明评估者的模型辅助诊断，不能确立人工偏好或导出资格。无操作、拒绝输出和 fallback 到 U 分开统计。

旧 NLP 特征保留为目标片段周边和全文诊断，可测量发生什么变化，并暴露漏检失败的检查。不能按复合臭味分数、到前期语料距离、分类器置信度或最大观察特征变化排名成功。两篇问题文章适合描述性案例分析；句子、操作和多名复核者不是独立文章复现。

## 全文读者材料包

候选、全文上下文复核和选择规则冻结后，才准备本地材料包。每项展示两个完整文章版本，排版、章节结构、视觉资源、链接和可用发布上下文相同。A/B 位置使用保存的固定 seed 分配，隐藏编辑者或模型身份。不显示 diff 高亮、目标标记、模型结论、NLP 分数、预期答案，也不以摘要替代任一文章。另留完整 diff 和身份键的检查视图，供读者回答后查看。

首个小会话每篇只比较一个候选与 U。事先规定选择：P 非相同、意义保留结论已解决，且独立判断解决冻结目标时优先 P；否则用合格 T 作可行性对照。两者都符合时，将未展示组保留在诊断报告。都不符合则记录无合格对照并继续 development，不请求无意义比较。报告时披露这种合格候选选择，不能据此估计 P、T 或部署政策的无条件成功率。

主要问题询问哪个完整版本更让读者愿意继续读。保留 A、B、无实质差别且两个都可以、两个都不可以、无法判断。可选反馈可指出意义或风格顾虑，以及仍令人不适的段落。已获读者指出问题的例子，不要求再次只看原文判断臭味，也不要求逐句标注。历史抱怨原话作为 provenance 保留，不作为答案提示展示。

这是承认此前暴露的定性 development 材料包，不是盲态独立 validation。隐藏版本身份不能消除对原文的熟悉。不必仅为声称统计严谨，就用重复全文对照增加维护者负担。后续正式读者研究须在新独立组上冻结对照、分配、多读者抽样和 precision 设计。

## 阶段门槛与自主下一步

| 门槛 | 必需证据 | 无需进一步用户输入即可进行的动作 |
|---|---|---|
| 来源可用 | 精确 provenance、历史反馈对齐、明确翻译与使用权处理、充分全文上下文 | 冻结合格 development 输入；恢复或排除不完整版本，继续其他文章 |
| 干预就绪 | 仅原文目标、锁定、操作权限、请求与预算身份、选择和分析规则均冻结 | 生成有限 P/T 提案，保留 U |
| 候选复核就绪 | 精确操作重放、范围检查、完整输出与 diff、独立全文上下文复核 | 诊断失败或不确定编辑，区分版本化修复 |
| 具体读者对照 | 至少一个非相同提案，模型辅助意义保留已解决，且有合理目标修复 | 冻结实际全文材料包、映射和完整诊断报告 |
| 人工偏好已知 | 直接读者响应关联精确材料包及 hash | 记录方向、实际提供的强度、缺失、保留顾虑和狭窄个人 development 解释 |
| 训练准备有依据 | 有用已接受编辑、使用权与语义接受、明确工作负载和评估计划 | 估算云 GPU 要求；不开始本地 SFT 或配置主机 |

如果没有文章有用且在范围内的目标，或全部候选失败，这也是具体诊断。在证据支持时，继续已授权来源恢复、测量修复或单独版本化的狭窄干预。不要没有明确假设就无限生成候选，不悄悄扩展到新产品任务，也不要再拿合成通知替代。

可自主完成的工作包括来源与 provenance 核对、完整性检查、仅原文计划、有限且已授权推理、独立模型复核、操作工具、诊断及最终可复核材料包。维护者不必批准每个常规步骤。

新的个人阅读偏好是只有真实读者能提供的外部证据，agent 不能编造。具体、有价值的全文对照存在且独立准备完成时，才请求偏好。改变产品范围、训练使用权未确立的材料，或获取承诺的云 GPU，分别在必要时成为独立决策。本 development 实验不需要 GPU。

## 必需报告

分别报告考虑过和合格的原始文章、完整性／翻译／使用权排除、历史暴露、尝试的 P/T 调用、原始失败、不修改输出、复核修改、意义保留失败或不确定、问题解决评估、fallback 数、可供读者的对照和实际人工结果。包含全部计划分母、精确输入／配置／输出身份、API usage／成本及缺失、全文产物路径。纳入版本控制的报告按 ID 和证据引用概述来源正文，不重新分发正文。

本批最强可能结果，是一项可追踪、保留意义且维护者在原媒体上下文中更偏好的修复，同时具体说明小模型基线限制。它仍不提供实测 SFT 增益、已验证通用臭味规则，或 online RL 的依据。
