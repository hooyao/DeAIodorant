# 小型精修模型：人工介入前的诊断审计

审计 ID：`compact-refiner-readiness-audit-1.0`

日期：2026-09-14

状态：前瞻性实现建议；撰写本版本时，复核者尚未获得候选结果。

## 决策

运行有限的 CR-001 development 流水线，再独立复核输出，之后才请求读者时间或选择训练硬件。本审计不启动 SFT、DPO 或 reward optimization。可执行的下一步是推理与测量可行性实验。

有用的自主结果，是关于编辑机会、内容保留、小模型行为或复核失败的可复现发现，不是人工继续阅读意愿的估计。没有人工判断时，即使人工介入前诊断阶段完成，读者实验仍为 `awaiting_review`。

本审计阅读路线索引、数据约定、评估政策、首批计划、训练计划、决策、实验账本、prompt 及报告和 manifest 模板。另使用已暴露的 reader-friction 和第二次干预标注，以及 2026-09-14 重新评估，作为 development 上下文。不检查历史预留集、封存测试或冻结的 87 个修饰语候选。

## 当前计划正确之处

不修改对照使拒绝编辑可观察。未微调小模型基线避免后续 SFT 与原文比较时，将 prompt 效果归因训练。保留失败候选，将模型复核与人工接受分开，避免把精美提案池变成虚构 gold。配对输入设计也无需先发现前后期语料特征差异，才能测试有用编辑。

首个实验应保留这些边界。主要风险已是任务相关性与可测量性，并非缺少更复杂训练算法。

## 需要可观察诊断的风险

### 来源任务可能几乎没有编辑机会

对完整、仔细组织的事实包作普通回答，可能已经很好。300-600 字限制排除了早期评论中的不少长距离漂移、重复结论和整合不良的说明。反过来，稀疏事实包配合最低长度可能人为制造填充。两种情况都不能确立自然问题 prevalence。

独立复核者看到编辑前，先单独检查每份来源草稿。记录未见候选时的编辑机会清单，并附证据片段：

- `actionable_local_issue`：可识别、在范围内的缺陷，且只用已有信息即可进行合理有限修改；
- `no_clear_edit_needed`：按约定没有识别实质缺陷；
- `content_correction_needed`：必需来源内容缺失、无支持主张，或其他风格编辑者不能悄悄修复的缺陷；
- `uncertain`：歧义、上下文不足或分歧，使诊断缺少可辩护依据。

添加可多选问题标签，例如冗余框架、所指不明、信息无序、语法别扭或风格不匹配。这些是编辑观察提案，不是已验证臭味类别。可操作标签至少保留一个证据片段和限定范围的理由；不只凭标记、长度或模型身份推断缺陷。记录复核者类别，以及清单是否在看到任何候选输出前完成。

不依据清单选择、重新生成或排除有效草稿。按来源模型和体裁报告全部类别。若大多数草稿无明显编辑机会，直接发现就是任务覆盖受限。后续独立版本批次可包含更长或更接近真实杂乱状态的输入，但生成前固定抽样规则。不要求差写作或刻板机器行文来挽救当前效应。

### 构造场景不等于自然写作分布

虚构名称和数量使事实可追踪、使用权可管理，不表示文章应写成虚构故事。所要求体裁、受众和普通交际目的保持真实合理。不新增轶事或个人经历，使修订显得更像人写。

醒目报告构造内容来源。虚构工作场景段落能测试约束，不能估计真实用户草稿多常需要编辑。熟悉度、风险程度和主题兴趣可能与真实阅读不同。合成 development 运行即使成功，后续评估仍需获得许可的真实感输入。

### 原文有效性与编辑保真是不同问题

双向对照事实包审计来源：提供的必需事实有无遗漏或改变，以及是否新增无支持事实。事实包内容遗漏若违反生成任务，即使文章流畅也是来源失败。任务不要求全部事实时，生成前在任务说明中区分可选与必需事实。实质来源问题进入内容纠正隔离区。

对准入来源，将每个候选与精确原始段落比较，使用编辑者收到的相同合法上下文和锁定内容。不奖励候选恢复原文没有的事实包内容；那是另一任务。不要把新的合理推论当成保留主张。检查所谓删除空洞框架是否也改变不确定性、范围、重点、归属或作者立场。未解决者标 `uncertain`，自动字符串检查无法裁定。

### 训练前候选比较就可能不对称

P 和 T 必须有相同可编辑输入、声明强度、受众、风格、只读上下文和合法锁定内容。主张清单和预期复核答案不是额外编辑输入。两组保存完整渲染输入及 hash，以便核查。

经助手反复推敲形成的 T 提案是有用诊断上限，却不是与 P 匹配的一次调用竞争者。记录 T 是冻结 API 响应，还是助手撰写或迭代复核提案，包括尝试次数和暴露上下文。只有可用时才报告观察到的延迟与成本；不可用的助手算力记未知。不要得出仅容量差距解释差异的结论。

独立模型复核者应收到不透明候选 ID，不接收编辑者或模型标签、确定性结论或期望答案。保真复核仍看到原文；这是候选身份盲态，不是人工读者盲态。分开调用或使用独立 agent 能减少直接自评，但共享模型家族与指令仍造成相关错误。一致不能变成人工 validation。

### 托管别名不能确立训练身份

记录请求和返回的来源或编辑模型 ID、可见时的 provider、checkpoint revision 或其缺失、reasoning 与解码政策、时间戳。单独确定可训练 student checkpoint 和 license。若无法证明精确 revision 等价，托管 P 只是近似基线。任何训练归因前，按相同输入约定重跑实际 base checkpoint 的未微调版本。不能假定最强可访问来源或编辑者代表全部部署生成器或全部中文体裁。

## 首次运行的精确产物与门槛

以下是建议加入 CR-001 冻结记录的内容，不声称产物或检查已存在。检查候选结果前，冻结定义及适用阈值。结果出现后的代码修复获得新诊断版本，并保留原结果。

| 产物 | 必需内容 | 门槛或解释 |
|---|---|---|
| 输入与请求 manifest | 24 个组 ID；构造来源和使用权记录；体裁与来源分配；事实包、prompt、request、代码、输入 hash；价格与费用上限 | 恰好一个不可变组分配；provenance 不缺失；模型或 prompt 变化均记录 |
| `generation_accounting.json` | 来源与候选已分配、已尝试、已完成、拒绝、不确定、未尝试计数；原因代码；全部尝试 | 每个计划 ID 都有终止或明确待定状态；失败请求不得从分母消失 |
| `source_audit.jsonl` | 双向事实包复核、必需事实遗漏、无支持新增、仅原文编辑机会清单 | 来源失败或不确定者隔离；不按编辑可能成功来选择 |
| `candidate_integrity.jsonl` | 原文及输出 hash、重放结果、保护片段、数量与单位、编辑幅度、精确不修改状态 | 所有下游候选通过重放与身份检查；格式错、截断或空结果不能算不修改 |
| `review_controls.jsonl` 及私有答案键 | 独立构造的同一性配对和植入语义错误的配对 | 对照不是自然样本或读者结果；复核漏检暴露操作层面的复核弱点 |
| `candidate_audit.jsonl` | 候选身份盲态模型复核；保留、删除、新增主张；上下文证据；pass/fail/uncertain；问题解决状态 | 严重失败或不确定阻止该候选进入可供读者复核状态；不修改候选不是收益证据 |
| `diagnostic_summary.json` | 以下计数和对照，明确仅模型 provenance 及缺失人工字段 | 不模拟人工答案，不给臭味分数，不导出正向训练数据 |
| 盲态读者材料包和私有映射 | 合格对照、固定分配、相同上下文与格式、诊断、条目 hash | 实际回答前冻结；不安全候选或复核提示不进入可见任务 |

首次复核 smoke 检查用两个同一性配对和四个构造严重变化对照。四种变化覆盖否定、不确定性削弱、量词或范围变化，以及表面实体和数字保持完整但所指改变。它们不属于 24 组。漏掉植入严重变化的复核者，不足以充当唯一的人工介入前语义门槛。保留漏检，在独立命名的 development 对照上修订后，才重新信任此门槛。通过六个对照不能估计通用漏检率或认证已接受数据。简单字符串规则可能漏掉范围或所指对照，但不因此推翻它声明的较窄用途。

运行层面完整的诊断需要有效 provenance、完整计账、可复现输出、明确复核结果和报告。即使没有安全编辑，也可完成。准备实质读者对照，还需至少一个非相同候选，其模型辅助意义保留状态已解决。这是资格条件，不是实用质量或读者样本量充足的主张。人工接受和现有导出政策继续控制训练资格。

## 事先指定的描述性分析

独立示例按任务组计，不把句子、操作、复核通过次数或多个版本当独立示例。本 development 批次用计数、分母和配对描述表，不对模型生成质量分数做显著性检验。

1. **来源覆盖：** 对全部 24 个分配组，报告完成、事实包失败或不确定、长度达标、编辑机会类别，以及来源模型按体裁的分布。连续报告来源长度；仅长度违规不自动成为事实失败或编辑机会。
2. **原始候选行为：** P/T 分别报告分配与尝试请求数、完整输出、精确不修改、非空编辑、格式错误、严重失败、复核不确定，以及合格可复核编辑。适用时同时保留全部分配分母与较窄有效来源分母。
3. **覆盖与安全：** 分别报告原始输出失败、拒绝输出、fallback 到 U、安全非相同编辑，以及自然不修改响应。不把 fallback 与成功不修改合并。
4. **匹配 P/T 诊断表：** 在相同准入来源组中，交叉列出意义保留结果与不修改或编辑状态，加入仅原文编辑机会类别。对无明确问题来源作了编辑，是潜在过度编辑案例，不自动算失败。
5. **独立编辑诊断：** 对每个结论已解决候选，记录原先问题已解决、未解决或被新问题替代。准则主观时用 `uncertain`。这是模型辅助问题解决评估，不是读者胜出。
6. **检查示例：** 私有附录保留每项严重失败和不确定。用确定性 hash 顺序最多选八个公开报告 ID，尽可能平衡体裁与来源，不只挑漂亮例子。完整私有文本留在 ignored 数据路径。
7. **运行：** 报告延迟分布、包括可见 reasoning 使用的总 token、实际成本或明确缺失、重试、finish reason，以及 checkpoint 或 provider 不确定。估计另行展示。

全部 24 个原始组在流失计账中保持可见。来源与体裁表的小单元格只描述这些任务说明，不能排名来源模型或确立子组普遍性。不要从本次最大特征变化或模型复核差异选择新 reward。

## 什么算具体发现

| 观察模式 | 有依据的发现 | 下一步 |
|---|---|---|
| 检查编辑前，大多数有效来源被标无明确问题 | 这个短构造任务集的模型诊断编辑机会有限 | 保留不修改示例；扩大标注前设计独立真实任务 development 批次 |
| 大量来源未通过事实包复核 | 来源生成或任务说明设计限制本实验 | 诊断必需事实覆盖和冲突指令；版本化来源任务，不改编辑 reward |
| 匹配输入下，P 反复丢失范围或主张，T 避免了这些错误 | 在这些 development 条目上存在具体小模型基线失败模式 | 保留 challenge 案例；测试适当版本化的政策修复；尚未测得 SFT 收益 |
| P 和 T 都在相同关系或风格案例失败 | 输入歧义或编辑约定可能是瓶颈 | 确定缺失合法上下文或收窄范围；不添加编造内容 |
| 安全非相同候选解决独立识别的问题 | 存在值得请读者比较的具体提案 | 冻结复核材料包，报告人工结果仍缺失 |
| 自动检查通过，语义复核发现实质变化 | 字面检查覆盖不完整 | 保留失败作 challenge，记录检查限制 |
| 复核对照失败，或复核者对重要内容有分歧 | 语义复核流程目前无法解决准入 | 保留不确定；收集正向导出前修复测量 |
| 全部路径返回 U 或大量依赖 fallback | 政策可能保守，但有用改写尚未确立 | 诊断来源机会或编辑行为何者限制覆盖 |

一个反例可以推翻普遍安全主张；少数吸引人的例子不能确立普遍收益。决定是否已有足够内容值得邀请读者时，明确报告这种不对称。

## 预算、执行与跟进

保留已记录工作上限：接口 smoke 请求 USD 1，CR-001 推理累计 USD 5。付费执行前，按实时价格、完整输入输出 token 上限、reasoning 政策、计划请求数和重试风险，保守估算最大费用。成功缓存不需付费重跑。记录成本不确定，不把 usage 缺失当零。若最坏估计超过上限，发请求前修订范围或单独记录预算决策。

首次诊断工作流只需 API 推理和本地 CPU 工具，还不需要云 GPU。本审计不下载权重、租硬件或启动本地 SFT。已接受数据、student 身份、sequence length 和训练工作负载确立后，硬件估算才具体。

约一分钟后检查进程存活、产物或日志计数增长、最后完成条目与终止状态，并在预计运行时长内分散检查约五次。Watcher 只辅助。不要仅因 watcher 超时就启动第二个写入者。失败时报告未完成请求和未知成本。

主 agent 提供产物路径后，本审计复核者可以独立完成两轮：先做仅原文编辑机会与一致性复核，再做候选身份盲态的保真和问题解决复核。打开第二轮前保存第一轮。同一复核任务不编写 T 候选。所有结果明确保持为助手或模型评估。下一次面向用户更新应呈现具体发现、限制和可复核材料包；不要请求 GPU 来弥补证据不足。
