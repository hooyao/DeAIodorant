# 撤回 Cowork 预览并纠正样例选择

日期：2026-09-14。决策：`CR-D023`。
状态：因目标不匹配而撤回读者任务；未记录 A/B 偏好。

## 维护者否定了什么

维护者此前已经指出 Cowork 文章的 AI 臭味较弱。尽管知道这一局限，助手后来仍准备了完整文章的改写，并再次请求阅读偏好。维护者否定了将 Cowork 作为典型中文 AI 风格强例的做法。它可能通过翻译继承英文 LLM 的缺陷，同时仍不适合作为目标中文现象的样例。这一区分不能确定文章的实际生成历史，也不能把翻译当成严重程度标签。

## 方法为什么偏离了目标

来源现成、语法问题可测量、解析 / diff 工具可用、原意保留评审已经完成，这些条件让 Cowork 很方便处理。助手将这些工程优势视为再次发起读者任务的充分理由，用一般可修复性替代了目标覆盖问题，重复了此前选择弱样例的错误。把任务称为可读性反馈，仍然没有解决它与当前特征发现优先级不匹配的问题。

支持译文是产品覆盖范围的要求，不能因此让这一篇弱例成为发现阶段的核心样例。同样，中文原创来源本身也不能使文章成为强例。

## 采取的行动

- 撤回待反馈的 Cowork 预览。维护者的意见属于样例选择否定，不能记为平局、原文胜出、改写落败、原意保留判定或测得的可读性结果。
- 保留全部原文与候选文本、操作、失败、回退、评审、句法分析、呈现产物、计数和反馈。
- 将已完成的修复运行保留为范围有限的工程及译文可读性证据。不得自动把另一篇已编辑文章塞进同一个读者请求，也不得换一个结果指标名称后再次发出 Cowork。
- 在生成下一篇改写或请求读者判断之前，恢复对真实完整中文文章的来源检查，寻找持续出现的目标风格。计数、孤立错字、普通 translationese 和无支持的事实断言，都不足以单独使样例具备强风格资格。
- 项目继续保留翻译、混合、中文直接写作及来源不明的来源过程。保留来源证据来解释差异；不从风格推断作者身份，也不全面排除译文。

## 记录与证据边界

`data/local/media-repair-development-v1/reader-preview-v1.1.json` 保留维护者两条原始意见，并记录原先未获回答的预览 hash。`ready-selection-status-v1.1.json` 更新读者就绪状态，但不修改原选择记录或候选 hash。原 HTML 对照保留为归档，不再承载正在进行的读者任务。
