# Microduck 的改写过程与读者反馈

日期：2026-09-15。维护者对第二版说：“这篇有一些翻译腔，但是总体来说还不错，至少没什么2025年后的AI的臭味”。完整原话与稿件 hash 另存于 `data/local/microduck-readable-feedback-v1/reader-feedback.json`，不回改之前尚未收到反馈的运行记录。

## 实际怎样生成

Microduck 全文由原生 Astra 编辑子任务处理，另一原生 Astra 子任务检查内容，Root 阅读原文与最终候选后交付。没有中英互译步骤、OpenRouter 调用或训练。先前保存的 GPT-4 Turbo 稿经过 Root 局部补充并获得维护者认可，这份 1519 字符稿在本次充当表达参考；Microduck 并非由 GPT-4 再次生成。

编辑者阅读全文、metadata 和现有引文，按直接陈述、明确话题和较短段落的方向重新组织内容。任务允许去掉重复预告和夸张渲染，同时要求完整保留金额、配置、来源、条件和不确定性。编辑者在保存 v1 前还做了自审，改过五处措辞；最初中间稿没有单独保存，不能把 v1 描述为未经修改的首次模型输出。

另一子任务随后对照全文，指出五处问题：补出无依据的介绍来源／设计意图、把原文没给399元报价扩大成外部没有承诺、弱化转让订单权益风险、把含混销售节奏固定为每4秒，以及将“耐折腾”具体解释成便于改装。第二版只修正这些位置，复核后未发现新的关键内容问题。编辑者与复核者属于同一模型家族，知道会话背景，并非盲评。

具体任务过程、角色与记录路径见 `data/local/microduck-readable-feedback-v1/method-provenance.json`。它是根据实际过程整理的说明，不能冒充完整运行时 prompt 或可逐字重现的后端状态。

## 具体改了什么

- 章节直接介绍配置、购买、DIY成本等内容。例如“账一：官方下单，买的是管线，熬的是时间”改成“购买条件与交付时间”。
- 信息按同一主题集中。训练部署后接 ONNX Runtime 故障；电池规格旁说明续航和加购电池；购买条件旁说明转让风险。
- 将短促的论断展开为关系清楚的说明。例如“训练靠算力，实机真不靠”改为开发者怎样训练、怎样部署，以及具体运行数据，避免让读者自己补足含义。
- 区分来源与结论。官方零件成本、网友散件采购估算、作者对DIY的建议分别表达，不合成一个仿佛已测试的成本结论。

按既有记录的读取口径，源文正文3231字符，成稿Markdown3443字符；标题和格式口径不同。这次没有大幅缩短文本，获得了正向评价，但字数相近本身不能证明信息完美保留或解释改善原因。

## 新反馈意味着什么

维护者对这份文章给出正向总体评价，仍感到一些翻译腔。至此，《亡灵遗产》局部稿与Microduck第二版各自有了具体的正向阅读反馈。不能再把Microduck标为等待首次整体评价，也不要求维护者重复同一判断。

“没什么2025年后的AI臭味”是对本稿的主观风格感受，不是时期差异统计、来源作者标签或对所有后期模型的结论。参考稿、指令、全文重排、自审和内容复核同时存在，当前也不能单独认定哪一步造成改善。没有新的阅读意愿量表、盲评或逐句标签。

Root认为，仍有的翻译味可能与部分名词化和偏书面的表述有关，例如“机载计算由……承担”，也可能与重复的“原文作者认为”等归属提示有关。这是编辑假设，维护者没有具体指认这些句子，不将其登记为人工问题标签。候选稿保持原样；归属所保护的不确定性也不能为了去掉书面感而删掉。

下一步复试合适的中文译文。一次有界离线选材检查了既有独立发现与契约检验目录的10篇metadata，没有找到明确跨语言翻译证据，因此没有将其中任何文章强标为译文，也没有向维护者提交弱样例。检查记录在 `data/local/translated-readable-selection-v1/selection.json`。需要转向已有明确译文证据的开发材料另行选材，学生模型和训练阶段仍未开始。
