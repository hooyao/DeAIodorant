# 公众信息文章改写试做：首份候选稿

日期：2026-09-15。目标与范围以[当前目标1.7](../../../target-feature-discovery.md)为准：让公众信息文章把问题讲清楚，让读者看得舒服，不涉及艺术文体或作者身份检测。

维护者已确认《亡灵遗产》原文“很臭”，并定位四处表达。原话与精确位置作为新的反馈记录保存，旧待答请求、原文和模型标注未回写。这一反馈只用于确定可改的真实样例，不能替代对改写稿阅读效果的判断。

## 本次具体改动

候选稿：[refined-article.md](../../../../data/local/style-intervention-v1/refined-article.md)。原文：[original-article.md](../../../../data/local/style-intervention-v1/original-article.md)。完整回放版本与记录在 `data/local/style-intervention-v1/`。

| 类型 | 数量 | 例子及边界 |
|---|---:|---|
| 直接介绍对象，减少讲解姿态 | 6 | 将“先说看得见的部分”改为“界面与物品管理方面”，将“看不见的部分更大”改为“游戏机制的改动更大”；比较方向及具体内容保留 |
| 中和读者低预期 | 已包含在上述6项中 | 将“门槛比你想的高”改为本段已有的高内存需求判断，保留玩家反馈、分档、来源和“更稳”的限度 |
| 长段按内容分组 | 4 | 版本要求／兼容原因／操作建议，存档风险／升级路径／备份，问题状态及后续观察各自分段；不改字词、标点或句序 |

保留了有用的开篇问题，没有把所有设问都删掉；暂不采纳删除视频玩家前置范围的提案。原先七项呈现提案保留，Root 最终选择六项，计数说明另存澄清。组合稿为 3,249 字符，原文为 3,255；这不是依靠大幅压缩制造改写差异。

## 检查结果

十项操作的原文位置均唯一匹配。原稿、呈现调整稿、仅分组稿及组合稿均可回放；数字顺序、引文顺序及原始来源 hash 保持。分组稿去掉新增空行后与原文完全一致。给读者的 Markdown 按原始块类型标出小标题，不额外修改正文。

未参与编写的 Agent 阅读完整原文和候选稿，十项均在明确许可范围内通过含义保留复核。其判断涉及具体事实、条件、引用、来源和篇章联系，不仅检查数字。允许变化的是本次针对的讲解预告、对读者预期的假设及相应注意力安排，不声称全部语用意义不变。

仍有内容边界：官网重开要求与升级补丁如何兼容，原文未解释；更新日志中出现某问题不等于已经修复；内存参考线缺乏当前文字中可核查的分档依据。这些未被编造的解释填平，也没有把审计备注塞进读者正文。更容易定位信息不等于技术事实已经核验。

## 展示与结果状态

Markdown 候选稿与原文已经生成，可以直接阅读。HTML 的文本覆盖、三个 tab 目标和十个修改对照项通过静态检查；浏览器 URL 安全策略拒绝打开本地 HTML，未绕过，因此未做视觉或交互验证，HTML 不作为已验证展示入口。

当前没有读者偏好、阅读速度或理解准确率结果。下一步收集的是这份稿是否更清楚、更顺畅、更少令人反感的反馈，不能再用“像不像AI”或标注字段整齐程度替代。单篇已知强例上的反馈也不构成跨来源、跨读者的效果验证。

本轮没有 SFT、DPO、RL、GPU 或外部 LLM 调用。
