# 停止依赖旧模型，转入新小模型SFT准备

日期：2026-09-15。维护者明确GPT-4.1只作旧模型文风例子，并要求使用正常Qwen，27B也算小模型，停止浪费时间在便宜API上。当前采用[官方27B BF16云端方案](../student-sft-plan-v2.md)，角色以 `configs/model-roles-v3.json` 为准。Root此前把旧模型扩成解题工具、又把学生限制在4B/9B和廉价接口，均已停止；下方仅保留已发生过程。

## 已停止的旧模型批次

停止前进行了4次Azure初稿生成和4次JSON定点修订，按管理计划价合计估算0.77026美元，Azure实际账单未知。原稿、11/3/2/13项精确编辑、Astra内容复核及Root后续收尾均保留；此后没有新增Azure调用，不再把它们提交为研究解决方案或自动导出SFT教师目标。

这批过程留下了可检查的问题：完整提示和参考稿没有阻止遗漏独立信息、把条件加强成保证、补造因果和链接；按复核修订又会复制回难读原句、增加时间相邻含义或留下断句。它们是本批输出的观察，不用于概括GPT-4.1在所有任务上的能力，也不抵销维护者此前对其文风的评价。

维护者关于“LLM刚出来没有这种臭味”的经验判断作为研究线索保留。现有例子表明目标写法不是生成文本不可避免的属性，但不将GPT-4.1当作最早模型或据此给全部早期模型、具体后训练机制下结论。

## 新学生的实际摸底

曾保存4B/9B官方资料并做9B托管摸底，现已停止，只保留历史。托管摸底未给Astra参考稿，但它也不能充当正式本地基座对照。

默认OpenRouter路由返回Darkbloom。两篇输出夹杂无关的阿拉伯文、韩文等片段，并出现数字和引文损坏。其目录部署标注FP4。这些输出不能作为可比较的模型能力基线。

随后为客户端增加provider/quantization显式限制，固定同价DeepInfra/BF16，保留相同消息、temperature、reasoning、seed和最大输出。Microduck本次未再出现上述明显多语污染，但仍保留“先厘清”“买的是管线，熬的是时间”和否定替换套路，并把漏tick写成丢包、补出实机依赖算法效率等结论。具体证据和6项诊断在 `data/local/student-baseline-bf16-v1/microduck/diagnostic-review.json`。

两轮合计4次便宜9B请求，OpenRouter报告费用0.00214532美元。服务商与精度同时改变，不能单独归因于量化；真实权重revision及完整采样默认值未知，不能把托管结果当作未来本地SFT前后对照。更完整内容与阅读评估仍需在锁定的本地基座上执行。

## SFT已经准备到哪里

当前Astra制作的、已获认可的Microduck稿形成一条development序列化原型。早期v1未带原网页标题，完整模板6895字符；当前v2补入原网页标题，27B模板完整文本6943字符，non-thinking前缀和正文字符边界对齐。模板没有generation标记，实际token级mask仍需检查；不能把字符数当token数，也不能把一条原型当训练集。

本机tokenizers官方wheel下载遭遇TLS握手失败，未关闭证书验证；没有下载权重或训练。已准备只在Linux云GPU执行的4B兼容短跑脚本：先检查完整序列和正文mask，再给文本层加LoRA，运行3步梯度并检验adapter保存重载。默认执行只做离线计划检查，已通过；实际云端组合尚未测试。

当前模型已改为官方Qwen3.5-27B原始BF16权重，revision为 `fc05daec18b0a78c049392ed2e771dde82bdf654`，权重约51.75GiB。27B模板字符和离线计划检查通过，两个静态验证P2已修复，云端尚未执行。下一项资源为1张80GB A100/H100、建议128GB RAM和200GB磁盘；先测基座及LoRA，显存不足再用1张96GB或2张80GB。首次预留1—2小时，按实例单价计费。详见[当前27B计划](../student-sft-plan-v2.md)。
