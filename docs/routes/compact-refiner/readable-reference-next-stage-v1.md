# 从“愿意读”的参考稿推进下一阶段

日期：2026-09-15。本文是执行安排，不代表下列实验已经完成。

维护者对 1519 字符的局部补充稿说：“这个局部补充稿挺好的，至少我愿意读”。这是项目主要产品结果的一条直接正向反馈。原话、文件身份和证据范围保存在 `data/local/readable-reference-v1/reader-feedback.json`。GPT-4 原稿此前获得“读起来就好多了”的评价；现在补回三处操作和故障信息后，维护者仍明确愿意读。这份稿值得保留为开发参考，不能被此前的内容保留 fail 覆盖。

这次没有逐项事实确认、随机盲评或跨文章泛化证据，也没有证明新版优于更短的 GPT-4 原稿。三处局部补充通过了含义检查，但整篇剩余的遗漏与表述改变尚未全部处理，因此还不是完整改写的训练目标。

## 1. 保留参考稿，完成剩余内容修正

已认可的 `data/local/gpt4-turbo-followup-v1/partial-restoration-v2.md` 原样保存。修订另建版本，先解决会影响理解或实际选择的问题：内存经验建议被强化为基本要求、下载渠道及两个安装包缺失、首次稳定版日期与维护者归属改变。随后检查玩法细节和后续版本信息，不用添加空泛段落恢复字数。

沿用既有 12 组内容复核，不重新扩张标注 schema。每一处修正说明原文依据、如何表达和还有什么不确定。对原文没有建立的内存门槛或版本兼容结论，不在改写中补成确定事实。已经讲清楚的三段原则上保留，仅在出现实质问题时再改。这个过程的完成条件是具体内容正确表达和可追溯，不是让维护者反复寻找剩余问题。

## 2. 换文章检验方法

下一篇使用 Microduck 全文 `https://post.smzdm.com/p/a70dm4ll/`。维护者早已明确评价为“恶臭”，无需再问强度。本文是已经暴露的开发样例，不能伪装成未见验证集。原文、标题、来源和 hash 已固定到 `data/local/readable-reference-v1/next-work-items.json`。

当前工作方式为：读懂原文要说明的事情及其条件，写成顺畅的中文，再独立对照原文找遗漏、归属和强弱变化，把有用信息补回合适的位置。记录少量具体修改，例如将事件串写清楚、减少反复设问和预告、让解释与证据相邻。它们用于理解有效编辑，不立即变成禁用词或加权 reward。

接着从保留语料里选择一篇有持续阅读问题的公众信息类中文译文，检验相同流程。具体文章尚未选定，不重用已撤回的 Cowork。Baidu 的“一般臭”也不改成干净负例。原有采集、来源分层、时间采样和失败实验全部保留；必要时才补采材料。

给维护者看的仍是完成内容检查后的实际稿件。主要关心是否愿意读、是否容易理解、哪里仍让人反感；不安排大批评分或继续使用没有明显问题的样例。原文／改写差异较大的原因在研究记录中解释，不把审计过程塞满文章。

## 3. 再让便宜小模型复现

有多篇可靠的开发改写和具体阅读反馈后，做小批量 prompt 试验。强模型编辑和复核使用当前 Astra 或原生 subagent；OpenRouter 只选择当时价格已核对的便宜小模型。复用已保存的 GPT-4 输出，不将此前的一次指定试写扩展成连续付费强模型调用。

分别观察学生模型能否写顺、能否保住信息、能否按核查结果回补。若它只需要更清楚的提示，就继续完善提示和流程；若有稳定且有价值的失败模式，再围绕这些实际缺口准备训练数据。跨文章的重复结果比在《亡灵遗产》一篇上无限优化更有用。

保留好读的文字作为参考，不把“看起来像人”当标签，也不训练作者身份分类器。传统 NLP 在此阶段用于辅助定位、检查与描述；句长、连接词次数或特征距离不能代替阅读结果，更不能直接变成 RL 奖励。

## 4. 训练与资源条件

当前不进入 SFT、DPO 或 RL，不需要 GPU。只有目标风格可以具体复现、成对数据通过内容检查、学生模型的能力缺口也清楚之后，才选择模型和训练方法。届时根据序列长度、数据量与训练配置给出最低／推荐 GPU 显存、主机 RAM、存储、软件、预计时长与费用，再使用维护者提供的云 GPU。

目前没有需要维护者额外决策的事项。当前稿修正和 Microduck 改写可以自主推进；出现需要实际阅读感受才能判断的完整结果，或确需资源选择时再提交。
