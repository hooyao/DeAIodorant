# 对比构式与读者议程框架

Protocol：`rhetorical-frame-measurement-1.0`。日期：2026-09-14。
状态：根据维护者明确定位的观察制定的探索性测量规范，本版本尚未开展新测量。

## 维护者的澄清

维护者指出字面 `而是` 是强信号，并解释 SMZDM 例句 `机载的不是 Jetson，是一块国产瑞芯微 RK3566 核心板` 使用单独的肯定判断词，表达相同的否定—肯定构式。表面省去 `而` 不改变该例中的纠正。将读者指出的构式保留为高优先级假设。不得将文章中字面次数为零视为反驳更广泛信号的证据，也不得悄悄改变历史字面计数。

维护者还将标题中的 `先把买、搓、等三条路算明白` 定位为强烈令人反感的信号。标题和章节标题必须作为整篇文章的一部分检查；仅统计正文不能覆盖这项观察。

## 两个独立的候选家族

### 否定—肯定替换或纠正

保持现有字面 `而是` 计数不变，在新分析中显式呈现该形式。另行报告一种实现：清单中的否定前缀后出现逗号或分号，其后紧接 `是` 或 `就是`。该边界允许空白。复用 `reading_burden.py` 中已冻结的否定前缀清单，不得悄悄扩充。

最近的合格否定前缀必须位于同一输入 block 中，且在最后一个 `。！？!?` 或此前已消费的对比连接词之后，以较晚者为准。嵌在 `而不是` 中的前缀不算新的否定侧起点。一个前缀不得复用于多个肯定分句。传入的 DOM block 内部换行不形成句界。本次输入是真实保存的 DOM block，不将采集器的文本行当成段落。

即使无法确定前缀，每个显式字面词也必须保持可观察。不得将前缀未确定的字面词悄悄称为已确认的配对构式。分别及合并报告显式配对与单独判断词候选；句法相似不能认证所有可能句子都具有语义等价关系。不改写原文句子。

逆序分类、固定清单之外的隐含否定、肯定判断词前插入主语或副词，以及更广泛的平行对比，均不在这个首版狭窄提取器的覆盖范围内。漏检是覆盖限制，不代表写得好。匹配构式可能传达必要区分，不自动等于冗余。

### 读者议程框架

定位 `先把`，其后需有非空主题，并接以下固定结果谓词之一：`算明白`、`说清楚`、`说明白`、`讲清楚`、`讲明白`、`捋清楚`、`捋清`、`理清楚`、`理清`、`弄清楚`、`弄明白` 或 `搞清楚`。
不得跨逗号、冒号、分号、句末标点或换行匹配。主题内允许中文顿号 `、`。

记录精确主题片段、顿号数量，以及标题、章节标题或正文角色。这仅将一种有限的认知组织模板操作化，不能捕获所有指令，也不能验证读者是否反感。取下电池等实际动作不在清单中。

保留标题中的三个缩略活动，以及将它们包装成三条路线的名词短语，以供语义解释。不得将该标题硬编码为唯一正例模式，也不预设所有列举都有问题。

## 范围、产物与约束

首先在两个关联原文的读者参照样本上运行：SMZDM 与 Baidu 的完整标题和 DOM block。保留所有匹配和未匹配观察；不推断语料库整体效应、准确率、严重程度排名、p-value 或 RL reward。两篇文章之间的语料、体裁和长度混杂继续存在。

在每条输入记录内保存从零开始、右端不包含的 Unicode offset、精确证据、前缀、标记与主题片段、实现形式和角色。分别报告标题、正文以及总候选覆盖。保留此前全部原文、反馈、分析和计数版本。输入、代码、protocol 和输出 hash 记录在 `feature_runs/reader-anchor-frames-v1/` 下的新私有运行中。

测试必须区分真正的单独判断词构式与 `是` 的普通用法，阻止跨句、跨 block 及重复前缀匹配，保留前缀未确定的显式字面词，验证精确 Unicode 片段，并避免把普通指令例子变成错误标签。候选提取与语义必要性、读者损害和编辑效果分别处理。
