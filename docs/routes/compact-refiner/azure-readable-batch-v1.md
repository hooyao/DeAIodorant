日期：2026-09-15。目标是把已有可读参考迁移到明确译文及不同信息文章，并检查少改是否可行。本批为已暴露 development，未打开旧保留集、final-test或87候选。材料和prompt在读取模型回答前冻结。

## 选材与输入

四篇分别为：InfoQ《为什么变更感知对现代应用程序的排障工作非常重要》（明确译文，全文修复主例）；InfoQ Nuxt Test Utils v4新闻（明确译文，保守编辑对照）；SMZDM Seedance 2.0短讯（短句组织与数量关系压力例）；新浪2022年扫地机指南（营销表达和技术参数边界例）。不把时间分组、来源类型或助手判断作为AI作者标签。后三篇均不要求维护者进行弱差异评分。

译文选材只读了原staging池24篇metadata/structure中的3篇完整正文，选出2篇不同用途的材料。此前已被撤回的Cowork及旧三份修复材料按来源身份排除，未读取其正文；先前已重筛为弱／模糊的extension后期12篇不复用。中文候选中，16242字符的长购买指南超出本批范围，图注为主的BB-8文未选；这不是对它们质量的最终判断。

代码、内联标识和正文在采集器的纯文本视图中存在人为断行。生成模型输入前，按已保存DOM块恢复可读段落和代码行，去掉“复制代码”按钮；所有其他非空白字核对一致。原始body和HTML不改，格式恢复单独记录，不能算作模型的阅读改善。图片未视觉核验，不给模型补充图中不存在于正文的内容。

## 冻结调用

统一使用已获正向反馈的Microduck第二版作为表达参考。指令要求完整编辑、明确关系、允许少改，保留独立事实、实例、条件、否定、不确定性和代码，不把全文缩成摘要。未把各篇的研究角色或人工评价传给模型，不按出现“而是”等词的数量打分。

使用用户授权的Azure deployment `gpt-4.1`，温度0，`store=False`，无工具和自动重试。没有请求seed，响应不公开具体checkpoint时继续记为未知。每篇最大输出按输入长度预先确定为11500、5000、3000、9500 tokens；请求timeout为120秒。首次最多4次请求，顺序执行，错误停止，不反复试写。

本批按已有10／30美元每百万token的管理用计划价控制在3美元内，沿用.env同目录的45美元中央账本和live缓存。计划价不是Azure实际费率；只报告token用量和估算，实际账单未知。修订需要看内容复核结果后另存，不能静默改首次输出。

## 复核与结果边界

每份原始回答保存原样，再由原生Astra任务对照可读源文、原始正文和代码作内容复核。查关键内容遗漏、主语与因果改变、数字范围、归属、版本及不确定性；代码／数字机械检查只是辅助。必要修订采用明确操作并另存版本，之后再次核查。

先判断是否有可交付的完整文字稿，再谈阅读感受。保守对照允许接近原样；没有明显改善机会时，不人为制造更大改动。得到模型文字或机器保真通过均不代表读者效果，不为本批赋予训练资格。

全部产物在 `data/local/azure-readable-batch-v1/`，原始来源与旧研究不改。当前不做训练，不请求GPU。若没有需要读者决策的实质差异，不重复向维护者发送相似的评分任务。
