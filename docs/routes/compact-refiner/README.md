2026-09-15 当前产品边界：让公众号、媒体解读、科普和技术说明等公众信息文章的读者看得舒服、把问题看明白。艺术文体及作者身份检测不在范围内。特征和标注辅助实际改写；当前已有[信息文章改写试稿](information-refinement-pilot-v1.md)，不再等待已收到的 n01 强度反馈。

## 决策与目标

维护者在 2026-09-14 暂停此前语料优先的臭味发现路线，选择本路线：用已接受编辑训练小型中文编辑模型，再用可靠的同输入偏好改进；只有经过验证的 reward 证明值得时，才考虑 online RL。

产品输入是完整真实媒体文章，包括已采集的 InfoQ 文章。产品目标是提高读者继续阅读的意愿，同时保留意义、事实主张、限定和作者风格。改善中文译文是必需能力，默认只依赖中文输入。翻译是 provenance 分层；仅含原创的筛选属于对照视图。原语言文本可用时支持诊断与核实，但不成为隐性输入要求。传统 NLP 提供低成本检查与诊断，不提供未经验证的通用臭味分数，也不提供作者身份目标。

```text
可追踪的真实媒体文章与对照足够鲜明的读者印象
    -> 可重复的目标特征发现与反例
    -> 带全文上下文和未修改对照的有限编辑候选
    -> 独立意义保留复核与盲评读者偏好
    -> 已接受编辑数据集
    -> 小模型 SFT
    -> 在 held-out 数据上与未微调模型及原输入比较
    -> 可选：基于可信偏好对的 DPO
    -> 可选：reward 验证后的 online RL
```

| 阶段 | 交付物 | 退出条件 | 当前状态 |
|---|---|---|---|
| R0：路线准备 | 版本化约定、prompt、运行与报告模板、决策记录 | 交叉链接、模板、环境事实和历史边界检查完成 | 已完成 |
| R1：开发基线 | 首批 24 个独立草稿组；未修改与编辑候选；复核结果 | 流水线可复现，意义保留复核可用，读者任务产生可解释证据 | 已记录三次人工预览反馈；展示配对缺少目标臭味覆盖，一项意义保留顾虑未解决 |
| R2：训练数据 | 版本化人工复核 SFT 示例，以及单独标注的偏好记录 | 使用权、组隔离、语义复核、不修改示例及导出验证通过 | 未开始 |
| R3：SFT | 在已接受编辑上训练一个小模型 | 独立比较显示，相对未微调模型有实用收益且保留内容 | 未开始 |
| R4：偏好优化 | 可选 DPO checkpoint 与 ablation | 存在可靠偏好数据，DPO 在同一门槛下优于 SFT | 有条件开展 |
| R5：Online RL | 可选 reward model、取巧审计和有限训练实验 | reward 能预测独立人工偏好，优化相对 DPO 有额外价值 | 暂缓 |
| R6：产品集成 | 可检查编辑、强度控制、逐项 fallback | 评估约定稳定，部署与运行要求满足 | 暂缓 |

数据数量预算是可行性选择，不表示统计 power。R1 不是 validation 研究。R2 可以以 200 个已接受示例作为工作目标，但达到 200 不自动授权晋级，也不表示模型已足够。评估规模由前瞻性 power 或 precision 设计确定。

可以在成功的 SFT 模型处结束。DPO 和 RL 是实验，不是必需升级。如果未微调小模型配合冻结 prompt 已达到实际目标，就保留该基线，不人为制造训练需求。

## 当前环境与执行

2026-09-14 观察到：Windows、Python 3.13.5、NVIDIA GeForce GTX 1080、8192 MiB VRAM、驱动 581.57。维护者报告无 `gx10` 访问。这是环境观察，不是已核实的训练兼容矩阵。

本地机器用于数据集构建、确定性检查、diff、统计和产物管理。维护者已排除 GTX 1080 上的 SFT，将在训练就绪时提供云 GPU。交接前，根据选定模型与训练工作负载，按[训练计划](training.md)说明最低及推荐硬件、兼容性、预计时长和成本。目前没有本地 SFT 或云配置工作。

按维护者最新限制，OpenRouter 仅用于快速、低成本的小模型；需要强模型能力时，由当前 Astra 或当前环境中的 Astra subagent 执行。历史强模型选型和已执行 API 记录只作历史证据，不构成恢复调用的授权。本次文档迁移不调用网络或模型 API。经核实的云训练环境仍是 R3 的独立前提。

仅将 ignored 根目录 `.env` 中的 `OPENAI_API_KEY` 加载到请求进程。不打印，也不写入 manifest。记录来源与目标模型 ID、可用时的提供者身份、解码与 reasoning 设置、prompt hash、usage、成本和错误。提供者不公开 checkpoint revision 时，精确复现可能受限，必须披露。

## 记录规则

每次运行前复制 manifest 模板、替换全部必需占位符、记录精确 prompt、配置和输入 hash，并新增账本条目。运行后完成报告，包括排除、失败、原始候选质量、fallback 行为和决策。始终将人工标注与模型辅助评估作为不同 provenance 类别。

结果出现前，protocol 修订需要新版本与说明。结果出现后，保留旧运行，将修订声明为新的 development 实验。绝不悄悄将探索性成功变为确认性结果。本路线不重开任何历史 final test。
