# CR-002：完整文章来源探测

Protocol 版本：`compact-refiner-full-article-source-1.0`。
状态：保留的提案；维护者确认真实媒体文章才是目标后，在执行前停止。本 protocol 未生成文章。任务文件完整保留，可作为辅助工程资源，不是下一项主要实验。参见[校准后的目标](../../target-feature-discovery.md)。

## 问题

普通全文写作请求能否产生可能包含读者目标现象的 development 输入？首轮预览使用受约束的简短通知或说明，未确立这种覆盖。

## 生成链前提

通过 prompt、来源请求、缓存响应、保存草稿和读者材料包 hash 核验原始文本。区分真正对来源文本进行的改写，与已经塑造行文的上游 prompting。保留审计和旧实验，不事后重新分类这些原始文本。

## 冻结的任务边界

使用 `experiments/fixtures/compact-refiner/article-tasks.v1.jsonl` 中四个任务。每项要求为指定受众和场合撰写完整的 1800-2400 字中文文章。每个请求只有一条用户消息，精确等于保存的 `prompt`。不提供示范文章、预写事实段落、风格指南、反套话指令、希望出现的臭味标记，也不要求写差。

来源任务有意允许普通概念说明。模型生成的具体事实主张、统计、来源或轶事均未经核实，应保留并标记；本次来源风格探测不授予训练准入或事实认证。

在两个经实时核实的模型 ID 上运行全部任务，计划生成八篇完整文章，对应四个底层任务组。同一任务的多个响应不是独立样本。保留全部完整响应和运行失败；不要反复重新生成有效文章，直到看起来足够公式化。

首次响应前必须冻结模型选择、目录价格、解码与推理设置、请求预算、输入及代码 hash，以及精确命令。默认输出预算 6144 token、temperature 0.7、支持时 seed 20260914，并禁用 reasoning。记录提供者未保证 seed 或 revision 的情况。这次有限探测使用 USD 1 API 上限，不使用本地 GPU 或训练。

## 完整性与复核

每篇完整返回文章保存为 UTF-8，并记录精确内容 hash。记录原始最终内容 provenance 和任何 parser 提取，但在来源复核前不改写、截断、清洗、删除标题或挑选段落。保留完整标题、章节标题、段落和结尾。

文章长度、段落数、finish reason 和是否存在无支持的具体主张，均为诊断。不把过短回答悄悄算作达到全文长度要求的成功，也不自动替换。来源准入不由风格阈值或作者身份分类器决定。

两位独立 agent 可以阅读匿名化全文，定位有限范围的证据：泛泛扩写、装饰性重构、缺乏支持的概念连接、重复组织或别扭的比喻语言。还必须记录有用修辞结构、清晰段落、反例和不确定性。这些是模型辅助的定位建议，不是读者标签。

任何提取片段都必须保留 offset 和全文链接；孤立片段不能替代主要的全文复核。若制作小型讨论材料包，应在事先规定的复核类别内使用固定的 hash 选取规则，披露选择过程，并保留全部原始文章供查看。

## 决策边界

如果 agent 复核找不到合理的目标覆盖，记录负面结果，先诊断 prompt、模型和任务范围，再扩展。如果发现具体候选，则为维护者准备少量仅含原文的全文复核。只有维护者能决定候选是否匹配其预期阅读体验。不要开始改写，也不要根据 agent 一致意见推断人工臭味标签。干净或不确定案例保留为对照。

这是新的 development 探测，不是恢复前后期分类、打开历史预留集、建立 SFT 数据集或验证 reward 的研究。
