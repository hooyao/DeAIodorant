# 自有DGX Spark上的首轮SFT执行安排

日期：2026-09-17。执行安排版本：`student-sft-execution-1.0`。这是换机后要落实的步骤；数据数量、正式trainer和GPU结果均未完成。它取代历史`training.md`中的1.5B—4B选型、段落输出、200条人工接受记录和云GPU前置安排；旧协议与产物保留原样。模型及资源依据见[27B方案](student-sft-plan-v2.md)，恢复入口见[HANDOFF](../../../HANDOFF.md)。

## 第一轮要回答的问题

用当前Astra制作、复核的完整文章改写对，对官方`Qwen/Qwen3.5-27B`做BF16 LoRA SFT，检验它能否在新文章上改善阅读感受，同时保住有效信息。目标输入仍是公众信息类中文文章，包含中文译文。先让模型学会完整编辑，不把连接词次数、作者身份或句法统计变成reward。

主要训练对照为同一官方基座使用同一编辑指令的输出；原文也必须保留，核对改写是否带来实际价值。教师稿用于教学和诊断，不把教师措辞的逐字复现当作产品结果。第一轮只跑一个配置、最多两个epoch候选；模型容量已定，不重新比价或做接口选型。

## A：先把8篇教师稿做可靠，再扩到首轮数据

先从既有允许用于discovery/development的真实语料和新采集材料中选择8篇，预先归入训练池：6篇有持续阅读问题的文章、2篇只需轻改或保持不变的对照，其中至少2篇有明确中文译文来源证据，至少1篇译文属于问题层。先读标题及全文，确认问题集中到足以值得编辑；用具体原句和上下文描述阅读障碍，不能靠年份、AI声明或“而是”次数替代。新的强度判断属于Astra筛选，不冒充维护者标注。

沿用已有采集与来源记录。译文来源未知时仍标未知，不为配额强标原创或翻译。发布日期是来源信息，不是训练标签；SFT不要求把新文章配给另一篇2023年前的文章作为目标。缺口需要补采时遵守网站现有访问限制。优先选择有足够正文和来源、能仅凭文字讲清楚的信息文章；图片承载了关键内容而尚未提取的，记录缺口，不能靠教师补造。

每篇按以下流程完成，保存每一版，不覆盖冻结材料：

1. **Astra编辑。** 输入原网页标题与完整中文正文，必要时附原页面确有的来源标记。参考Microduck的表达方法，把同一主题的信息放在一起，让判断、根据、条件和结果相邻。先读懂再全文编辑；可重排、拆句、合并重复表达，保留有效细节。已经顺畅的内容允许不动。不给学生或目标文章添加亲历、背景事实或读者误解。
2. **另一原生Astra任务检查内容。** 对照完整源文，检查数字、单位、版本、引文、说话者、条件、否定、不确定性、例子及操作后果。整理简短的遗漏/新增/强弱变化清单，逐项引用源文依据。确定性字符串检查仅作辅助；同模型家族复核不是独立人工事实认证。
3. **Root检查阅读。** 通读成稿，关注连续设问、预告、强行纠正认知、夸大程度、动词关系含混、话题跳转和机械归属提示。观察改后是否仍需读者自己拼接意思；不是把禁用词换成同义词。保真回补不能把难读原句整段抄回，也不为“自然”删掉重要限定。
4. **有限修订。** 先保存初稿，最多两轮针对已列问题的修订并复核。仍有实质问题的另存隔离；替换选材或修正教师流程，不把它凑进训练集。清单只用于审查，不把解释、审查备注或内部推理写进目标文章。
5. **登记准入依据。** 内容问题已处理、Root愿意通读，才标为本轮模型复核通过的教师对；单独保留`reader_feedback`是否存在。无人类反馈的样例如实标为未收集，不称人工gold。正常对照可以以原文作为目标，但须同样复核，不能随机复制充数。

8篇用于暴露流程问题，不安排维护者逐篇打分。若某类文章反复产生遗漏或难读回补，先修教师指令/复核方法并另存新批次；不要扩大有问题的数据。通过的8篇可计入下面64篇训练材料，因为其训练归属在制作前已固定。

## B：按文章来源隔离64/12/24篇

首轮总预算100篇不同来源文章，具体URL尚未选定。以下是有界试验规模，不是统计代表性或足够训练的定理。

| 集合 | 数量 | 有持续阅读问题 | 轻改/不改对照 | 其中明确译文至少（其中问题篇） |
| --- | ---: | ---: | ---: | ---: |
| `train` | 64 | 48 | 16 | 16（12） |
| `dev` | 12 | 8 | 4 | 4（3） |
| `pilot_eval` | 24 | 16 | 8 | 8（6） |

译文数包含在各集合总数中，不是额外文章。直接中文、翻译、混合/改编、未知分别保留真实来源类型；尽量覆盖多个媒体来源和消费科技、技术解释、科普等题材，不把一个站点的一种文风当全部目标。配额不足应报告并补采，不能把弱问题文章换个标签凑数。

先查既有split归属，再按canonical URL、正文hash、近重复和上游出处构成来源组；原文、译文、转载、改编以及所有修订跟随同一组。已经用于研究调试的来源组不能进入新`pilot_eval`。先保存分组清单和分配seed `20260917`，再制作目标和训练；发现跨集合关联则先隔离处理，不在看过评估输出后偷偷换文。来源与主题分层需尽量在各集合覆盖，报告实得组成。

`train`和`dev`共76篇需要通过上述流程的教师目标。`pilot_eval`先封存源文、来源、原文内容核查清单和样本分配，不需要先写24篇教师答案，更不能给编辑者当参考。其“未见”指未用于教师流程调试、训练和checkpoint选择；采集或来源核查角色可能读过源文，不能声称所有研究者严格盲法。

每个训练/开发记录最少保存：来源组和split、标题/正文路径与hash、来源类型及证据、教师目标路径与hash、编辑和复核版本、准入/隔离原因、真实人类反馈状态、准确messages。已有数据约定可复用，不为本批扩大通用schema。记录来源的公开许可信息或未知状态，不因网页可访问就声称已确认训练或再分发许可。

正式导出为`messages=[system,user,assistant]`：user仅含标题及中文正文，assistant仅含完整成稿。源文中已有的必要信息和来源标记可保留；英语原文可用于研究核验，但不得把只能从外文获知的新事实写入中文输入不可支持的目标。教师参考稿、复核清单、答案键、作者身份、年份标签和分析分数不进入学生messages。

以下是正式首轮拟用的标准编辑指令，标识为`student-article-editor-1.0`；在首次正式运行前写入manifest并对基座和SFT保持完全相同。它新增“允许保持原样”的明确约定，旧Microduck原型文件保持原样，只用于兼容性。

> 你是中文信息文章编辑。请将原文编辑为自然、清楚、便于阅读的完整中文文章。把相关信息放在一起，写清楚对象、条件和前后关系，减少重复铺垫、夸张渲染和机械化表达。保留有用事实、数字、版本、例证、说话者、条件、否定和不确定性，不增加新事实，不缩成摘要。已经清楚顺畅的部分可以保持原样。原文代码逐字保留。只输出编辑后的标题和完整正文。

第一轮只有一个标准编辑档；不要在这次试验里同时搜索多个强度、多个prompt或多个模型。多档强度和产品运行时回退另作后续功能，不能声称当前已经实现。

## C：先在Spark测运行条件，随后补正式trainer

设备为维护者自有DGX Spark，优先它。模型与revision固定，BF16，不训练视觉模块。根据[资源方案](student-sft-plan-v2.md)核实aarch64、GB10驱动与容器，再跑现有离线检查、完整基座生成和3步兼容检查。不要把其128-token默认短生成当完整文章验收。

现有3步脚本的学习率为`1e-4`，只验证接口。正式训练从原始BF16基座和新初始化LoRA开始，绝不续用已在Microduck开发原型上训练过的probe adapter。正式dev/评估基线使用上节正式指令，不把旧prompt或托管9B输出充当对照。

必须补齐下列工程能力后才能训练；以下路径是**待实现交付物，不是现有可运行命令**：

| 待实现交付物 | 必须完成的行为 |
| --- | --- |
| `experiments/prepare_student_sft.py`及可复用数据模块 | 校验准入、来源分组、hash与messages绑定，输出train/dev；锁定tokenizer测完整长度、正文mask和EOS，不导出`pilot_eval`目标 |
| `experiments/train_student_sft.py`及训练配置 | 多文章加载、动态padding、累积梯度、开发loss、固定epoch保存、断点恢复、实际版本/内存/吞吐记录 |
| `experiments/evaluate_student_sft.py`及逐文报告 | 相同输入和生成设置运行基座/选中adapter，保留原始输出、停止原因、完整性、内容复核和阅读比较 |

先实现够这一轮使用的最小入口，复用现有工具，不重搭通用训练平台。对跨split重复、错误源文绑定、prompt/padding参与loss、边界token误标、截断被记成功、恢复后数据顺序/步数错误写必要测试；不要以测试数量代替GPU实测。

tokenizer必须使用锁定revision及官方non-thinking模板。当前模板没有`{% generation %}`，不能直接依赖`assistant_only_loss`开关。每一条都检查：prompt、角色头、non-thinking前缀、padding被mask；目标正文和正确的assistant结束token参与loss；有监督token非空。特殊token可能没有普通字符offset，不能统一当正文或统一删除；边界不一致应失败并诊断。训练前解码核验完整目标，保存mask摘要和少量可复核边界，不将原文写入常规训练日志。

若`pad_token_id == eos_token_id`，必须依实际padding位置/attention mask区分补齐位置与真实结束token，不能按token ID一刀切mask。确认模型forward内部的label shift，避免collator再shift一次。adapter重载成功也不代表断点续训正确；正式恢复必须核验optimizer、scheduler、RNG、数据顺序和已完成的optimizer step。

先用8K完整输入加目标预算测量。不得截掉标题、结尾或限定来塞入显存。超长文章放入明示的长度缺口清单，记录各来源/问题层的覆盖损失；优先验证更长序列的内存优化。首轮确需限定长度时，在训练前固定范围并明确不覆盖超长全文。分段重写需要单独验证篇章衔接，不悄悄把全文任务改成句子任务。

## D：第一轮正式SFT的暂定配置

下面是有界起点，不是已验证最优配方。Spark兼容性、token长度和实际目标模块确定后，先冻结配置及数据hash，再开始首轮。软硬件不兼容导致的调整要记录，不能把多次试跑写成一次预定实验。

| 设置 | 首轮值/规则 |
| --- | --- |
| 基座 | `Qwen/Qwen3.5-27B`，revision `fc05daec18b0a78c049392ed2e771dde82bdf654` |
| 精度与方法 | 原始BF16基座，LoRA；不默认QLoRA或全参数微调 |
| LoRA | `r=16`、`alpha=32`、`dropout=0` |
| 目标模块 | 从实际语言层解析可支持的Linear；逐项审查和保存名称、可训练参数数目，排除vision/visual、lm_head和MTP；不可照抄另一种Qwen架构的名称 |
| 训练长度 | 起步完整输入加目标8192 tokens，训练前按全批测量及Spark峰值确定 |
| Batch | microbatch 1，gradient accumulation 4；单机effective batch 4 |
| Epoch与更新数 | 最多2 epochs；64篇时每epoch 16次optimizer update，共32次 |
| Optimizer | AdamW，`lr=5e-5`，`betas=(0.9,0.999)`，`eps=1e-8`，`weight_decay=0` |
| 学习率调度 | 前2次optimizer update线性warmup，随后constant；不做同批大网格搜索 |
| 梯度 | norm clip 1.0，gradient checkpointing；训练关闭`use_cache`，累积窗口按实际目标token数归一化loss |
| 批组织 | 每epoch固定seed洗牌，动态padding，不packing，不允许跨文章attention |
| Seed | `20260917`；记录库版本和实际确定性限制，不承诺不同kernel逐位相同 |
| 保存 | epoch 1、epoch 2的adapter及可恢复训练状态；权重/optimizer留在忽略的`models/`，发布数据清单、配置、摘要和hash |

这32次更新只用于检验能否开始学到编辑行为，不能承诺解决文风或跨领域泛化。正式开始前，用训练池中的代表性长样例在隔离probe目录测连续完整步的内存和吞吐；这些probe adapter全部丢弃不用，从全新adapter开始正式轮次。OOM先定位激活、logits、加载副本或kernel问题；不因单次OOM重新要求换云卡。

运行时约1分钟检查真实进程和日志，之后在预计总时长内分散检查约5次；完成以退出状态、checkpoint和验证结果为准。记录已处理完整tokens/s、监督tokens/s、optimizer updates、峰值统一内存及系统余量、停机原因。训练时间按`实际train完整tokens总量 × epochs / 稳态完整tokens/s`估算；基座生成、开发生成、评估生成和安装另计。

例如64篇平均6000 tokens、2 epochs是76.8万训练tokens，不是先前费用举例中的120万。评估还需基座和SFT各生成24篇，两个epoch的开发检查也占GPU时间；不能把以前“少量生成检查”的12—36小时估计直接套给全部工作。

## E：只用dev选一个checkpoint，再看新文章

先固定基座与SFT的推理指令、完整输入、模板和解码：`enable_thinking=False`、`do_sample=False`、相同输出上限；4096 new tokens仅作开发起点。若开发阶段不足，先修订全轮上限并冻结，不能按评估单篇结果增加重试或挑选最好一稿。保存原样输出，禁止先由Astra润色学生稿再当作学生效果。

在12篇dev上比较epoch 1与epoch 2。固定选择顺序：先排除有未解决实质内容错误、截断或空输出的checkpoint，再比较8篇问题文章的继续阅读意愿与理解难度，确认相对原文有改进、4篇对照相对原文未出现有害编辑；并列优先epoch 1。开发loss只作学习诊断，不用最低loss直接决定最好读。若两个都未通过，则本轮无候选，不读取24篇`pilot_eval`。

选出一个候选且冻结checkpoint hash后，才解封24篇`pilot_eval`。对照至少包括原文、官方基座编辑稿、SFT编辑稿，主要比较SFT与基座，也检查SFT相对原文的价值。先做逐文内容检查；失败、截断或两稿都差的文章仍留在分母，不能删除后只报告“可评部分”的偏好。

内容复核与阅读比较使用不同原生Astra任务，隐藏输出的模型/epoch身份并随机排列A/B，记录其实际可见上下文；同家族评审仍只是模型辅助结果，不能称独立人工盲评。报告每篇与每个来源层的：继续阅读倾向、具体阅读障碍、内容错误及严重程度、未解决事项、完整性、篇幅和对照上的不必要改写。数字或连接词变化不直接作为好坏分数。

第一轮进入下一批扩充的工程门槛预先定为：24篇SFT原样输出均无未解决实质内容错误、空输出或截断；16篇问题文章中，SFT相对基座和相对原文的两项阅读比较分别至少9篇明确获偏好，平局/两稿都差不算赢；8篇轻改对照相对原文没有明确阅读退化。译文问题层在两项比较中也都必须单独出现多数偏好，不能靠非译文平均值遮盖失败。基座的内容错误单列记录，不因为基座失败阻止合格SFT；同样不能因基座很差就让仍比原文难读的SFT通过。这个小样本门槛只是筛选下一步的默认规则，不是统计显著性或产品验收证据。

模型辅助门槛通过后，再给维护者一次少量完整文章阅读对比，包含直接中文和译文。展示来源在看输出前按层固定，不挑赢得最明显的样例；不再让维护者重评旧锚点或逐句给全部训练材料找错。已有两篇参考稿的认可不能替代对新学生输出的阅读反馈。即使过门槛也只说明值得继续，不能直接宣布产品完成。

`pilot_eval`读过后即为已暴露评估；若用其错误指导下一轮修改，下一轮需另备未用于调试的文章，旧24篇仅作回归。保留全量输赢和所有失败，不能换文后仍声称同一冻结评估通过。

## F：结果对应怎样的下一步
