# 小型精修模型评估

政策版本：`compact-refiner-evaluation-1.1`。

本路线政策定义结果与保护措施。每次读者评估或训练运行，都必须在结果出现前冻结样本、分配、精确对照、分析和决策阈值。目前尚未冻结或运行 held-out 评估。

## 基线与归因

| 组 | 含义 |
|---|---|
| U | 未修改草稿 |
| P | 使用冻结编辑 prompt 的未微调小模型 |
| T | 强助手或模型的编辑提案，记录 provenance |
| H | 可选的独立人工编辑候选；不能与 T 互换 |
| S | SFT 小模型，输入和评估约定与 P 相同 |
| D | 在阶段依据充分时，由 S 初始化的 DPO 模型 |

SFT 主要比较 S 与 P，S 与 U 是必需的产品价值比较。DPO 主要比较 D 与 S，同时保留 U 和 P。只把训练模型与原始草稿比较，无法识别训练价值。教师或人工候选帮助诊断可达质量，不自动成为 gold。

匹配输入、上下文和强度，使用固定解码策略。记录实际推理身份。没有 revision 证据时，不假定托管别名和本地训练 checkpoint 是同一 base model。

## 必需的中文译文评估

对直接中文、译文、混合或改编、provenance 未明各层的完整中文输入进行评估。外文原文是可选的整理或核验证据，不进入标准模型输入。若评估可选原文组，须单独披露和报告。

对译文输入和总体分别报告读者偏好、实质意义保留失败、复核不确定、不修改或 fallback 率，以及覆盖。评估前冻结足够的译文输入覆盖；由直接中文文章主导的合并结果不能确立这项必需能力。原语言文本和全部衍生译文或改编放在同一 split。翻译 provenance 与输入难读都不自动构成排除。连贯译文保留为不修改对照。

## 先检查意义保留，再测偏好

每个输入建立独立的主张与约束清单，足以复核重要内容。清单构建属于 development 或评估整理；其结论不进入模型输入，也不成为秘密提示。生成器只看到用户合法提供的锁定内容和上下文。

先运行确定性检查：操作重放、精确保护片段、带单位数字、命名实体或术语、日期、引用和编辑边界。再复核命题保留、entailment、归属、否定、情态、范围、所指和行文风格。复核者必须结合上下文检查修改片段；匹配预选字符串不证明意义保留。

严重失败包括改变事实命题、无支持新增、数量或实体或引用错误、否定反转、不确定性或归属变化，或作者意图实质变化。任何检测到的严重失败，都阻止该 checkpoint 晋级，直到评估新版本。未解决的意义保留判断也阻止该编辑准入。

Fallback 返回原文并记录原因代码。分别报告原始候选失败率，以及最终系统失败或 fallback 率。总返回 U 的系统安全，但没有证明改写收益。零次观察失败仍有非零不确定性上界，不代表零风险。

## 读者评估工具

主要问题：哪个版本更让读者愿意继续读？

选项：

- A；
- B；
- 两个都可以，没有实质差别；
- 两个都不可以；
- 无法判断。

评论可选。不要求语言学标注或作者身份分类。感知公式化程度、清晰度和行文风格，可以在计划子集上作为诊断，不能替代主要结果。

读者看到相同周边上下文和视觉格式，隐藏生成器身份与候选标签。随机化 A/B 位置和任务顺序。跨读者 counterbalance 对照，避免一位读者看到同一草稿所有版本。会话范围有限，保留未完成提交，不填补结果。

事先指定少量同文和镜像重复诊断，不计为处理组胜出。记录位置偏好、重复一致性、无法判断和缺失。通过少数对照不证明无偏差。如果诊断使某次会话无效，保留记录、解释规则，不将其重新解释为操作有效性证据。

## Development 与 validation

R1 是可行性研究。一位读者可以支持有记录的个人 development 方向，不能支持总体偏好主张。三组[定性预览](reports/cr001-reader-preview-v1.md)已有直接人工反馈，包括意义保留顾虑和无明显臭味观察。它不是受控读者研究，也不是独立语义认证；agent 或模型判断不能填补这些缺口。

Validation 运行需要新的组、冻结的候选生成器或 checkpoint，以及独立读者与条目交叉的分配计划。按预期平局率、读者及条目差异，通过 simulation 或明确 precision 目标设定样本量。不要将 development 中最大效应直接用于 power 计算。同一文档或同一人提供更多判断，不等于独立抽样。

冻结 final-test manifest，不打开其中的文本用于特征、prompt、reward 或 checkpoint 开发。Validation 可以在事先指定的少量配置中选择；选择后 final test 只运行一次。后续修改需要新的独立 final test。历史预留集继续封存。

## 分析约定

分别报告胜、负、都好的平局、都差的平局、无法判断、缺失和意义保留失败。描述性净偏好为 `(wins - losses) / eligible judged comparisons`；同时报告仅明确胜负样本中的占比及分母。绝不只报告明确胜出的比例，掩盖高平局或 fallback 率。

数据充足时，事先指定含读者与条目效应的 pairwise 或 ordinal 模型，或其他有依据的 clustered analysis。按计划保留体裁、来源生成器、长度、强度和不修改案例分层。小规模 development 数据报告考虑聚类的描述性区间及限制，不拟合缺乏支持的高维模型。

Validation 结果出现前，定义最小有用偏好提升、可接受运行成本、不确定性准则和分析对照。每阶段最多两个主要对照，事先规定 multiplicity 处理。不在看过结果后选择胜出的子组或阈值。

## 晋级与停止决策

| 观察 | 决策 |
|---|---|
| 严重意义保留失败 | 拒绝晋级；调查并创建新候选版本 |
| 读者或会话证据不可靠 | 在 development 数据上修复评估工具；不推断模型质量 |
| S 优于 U，但不优于 P | 训练收益未确立；保留或改进 prompt 基线 |
| S 按冻结的有用收益准则优于 P 和 U，且意义保留与成本门槛通过 | 在已评估范围内推进 SFT checkpoint |
| D 未优于 S | 保留 S；DPO 并非必需 |
| 区间很宽，同时覆盖有收益和无收益 | 无定论；值得时按冻结政策补证据 |
| 效果仅限一位读者或一种体裁 | 声明较窄适用范围；不声称普遍性 |
| 高安全主要依赖 fallback | 报告低覆盖；改写效果仍需证据 |

## 传统 NLP 的作用

当前特征先作为版本化诊断保留。有用候选包括编辑幅度、受保护内容变化、重复、局部修辞复现和篇章连续性。不能仅因某个现有臭味代理计算便宜或与发布时间相关，就授权其作为主要 reward。

引入辅助风格 reward 前，先冻结它，再检验特征变化在考虑内容保留和编辑幅度后，能否预测独立的同输入人工偏好。报告反例和覆盖。与去掉该特征 reward、其他训练配置相同的方案做 ablation。

有意探测 reward 取巧：删内容、缩短但不合语法、给受惩罚标记换同义词、标点碎片化、填充分母、一律不修改，以及削弱主张的风格变化。不带来读者收益也能提升的特征，只能保留为诊断。辅助分数收益不能抵消意义保留失败。

## 必需的结果表

每份模型报告包括 base 与 checkpoint 身份、独立组和读者数、候选数、偏好分类、原始严重失败、复核不确定、fallback 或不修改率、覆盖、编辑幅度分布、体裁及生成器分项、延迟、token 使用、成本、观察到的内存，以及全部排除。区分实测值、估计值和缺失字段。
