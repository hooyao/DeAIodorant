# 公众信息文章的有限改写试做 v1

日期：2026-09-15。目标：**让读者看得舒服，把问题讲清楚，同时保留原意和有效信息。** 本试做只处理公众信息文章，不涉及艺术文体。

## 输入与可归因范围

使用维护者已明确评价“很臭”的《亡灵遗产》完整文字视图。它是已经暴露的开发样例，不能作为独立验证。原文、来源、首次标注与人工反馈均不改。

编辑者先提出七项呈现调整，随后提出四项长段分组。Root 在生成候选稿前选定六项呈现调整：保留有用的开篇问题，只移除“结论先说”；暂不接受删除 b017 视频玩家前置范围的提案，以免争议边界进入第一版。原提案保留，Root 选择另存 `reviewed-edit-plan.json`。

四项分组只增加空行，不改原词、标点、句子顺序或引用。它们用于让版本要求／原因／操作建议、存档风险／升级路径／备份建议、不同故障状态以及后续观察对象更容易区分。本轮不声称已解决所有句内歧义或论证缺口。

## 四份可回放版本

- `original`：未修改文字。
- `style`：六项呈现调整，直接介绍对象和条件，减少讲解预告与读者低预期。
- `grouping`：四项长段分组。
- `combined`：组合上述十项，作为待审阅候选稿。

保留单独版本便于后续诊断，不能仅凭组合版本的偏好就归因到某个词或某个操作。当前先审阅组合稿，不给维护者安排大批评分任务，也不伪称已识别原文的读者处于盲态。

## 信息保留与允许变化

数字、版本、单位、实体、引文、来源归属、否定、实际操作条件、建议及其强弱都必须保留。作者对核对来源的声称继续以原文形式保留，不认证为实际核验。

本次明确允许改变的是讲解预告、对读者认知状态的预设和表达姿态。这些本就是所针对的问题，因此不声称全部语用含义严格不变。保留“游戏机制的改动更大”的比较，不把“更稳”改成流畅保证，不为内存分档补测试，不把更新日志中的出现改成已经修复。

先机械检查精确操作位置、数字顺序、引文顺序、分组的非空白字符一致性和原文 hash，再由未参与编写的 Agent 对照全文复核含义。存在实质保留风险时撤回对应操作，另存新版，绝不静默修改首次提案。

## 读者结果与停止条件

主要问题是修改后是否更容易读懂问题、更愿意继续读、是否减少惹人反感的表达。作者身份猜测、AI detector 分数、文采和特征距离都不是结果。

当前仅产出候选稿及审阅材料。没有实际读者反馈就不宣布有效；一次已知样例反馈也不作为普遍效果证据。若只有形式变简而仍难读，应回到具体措辞、信息分组和必要连接继续处理，不能用字段或分数好看替代体验。

本轮不处理无法从原文获得依据的技术争议。那些问题保留在编辑备注中，不靠编造前提补平，不把审计说明堆进面向读者的正文。
